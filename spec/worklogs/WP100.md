# WP100 — Theme tokens and a theme selector

Phase W's fourth WP. The shell's graphical furniture can now be swapped without touching markup or
structural CSS. Two themes ship, and a title-bar picker switches between them live.

## What landed

- **`static/app.css`** was rewritten as structure only. It defines no custom property. Every
  colour, font family, title size/weight/alignment, frame and rule weight, nav alignment, accent
  width, and chevron size is a `var(--…)`: 51 tokens, up from about 30 colour-only ones. The layout
  rules are the same as WP97-99's apart from what needed a token to exist:
  - a nav-item separator rule;
  - the chevron `::after`;
  - a frame on the sidebar and main pane;
  - a `--main-bg` for the content pane;
  - a `.page` max-width wrapper, so the pane background fills the column while the content stays
    72rem wide.
- **`static/themes/classic.css`** holds the WP97-99 values, moved out of `app.css`.
- **`static/themes/sketch.css`** follows `examples/ui/main_ui.png`:
  - a centred title;
  - monospace step labels centred in a column, with 3px black rules between them and downward
    chevrons joining them;
  - a grey current step;
  - a grey content pane with the step panels as white cards;
  - an inverted dark variant.
- **`chummer5.web.prefs`** is new. It holds `Theme`, `THEMES`, and `DEFAULT_THEME`.
- **`ChargenSession.theme`** stores the session's theme.
- **Templates:**
  - `base.html` links the theme first, through the new `_theme_link.html`, then `app.css`.
  - The title bar gained `.app-shell__prefs`, a form with the theme `<select>` (`hx-post`,
    `hx-trigger="change"`, `hx-swap="none"`).
- **`POST /ui/prefs/theme`** (`routes/pages.py`) validates the slug (422 if unknown), stores it,
  and returns the new `<link>` with `hx-swap-oob`.
- **`app.py`**: the `chargen-changed` middleware skips `PREFS_PATH_PREFIX` (`/ui/prefs/`).
- **`tests/unit/test_web_themes.py`** has 11 tests.

## Decisions

### Themes are complete token sets; `app.css` has no defaults

The full argument is in the decisions log. The short version: with defaults in `app.css`, a
misspelt token in a theme fails silently to the default, and Classic is an empty file. With
complete sets, the test suite can prove three things:

- every token `app.css` reads exists in every theme;
- a dark block only redefines tokens the light block has;
- a theme file is literally `:root {…}` plus `@media (prefers-color-scheme: dark) { :root {…} }`,
  holding custom properties only. This is the entry's acceptance.

The parser is deliberately a strict whole-file regex rather than a CSS library, and it has its own
negative test: a smuggled selector and a smuggled plain property must both fail. I mutation-checked
the completeness test by deleting `--nav-chevron-size` from Sketch; it fails and names the token.

`color-scheme: light dark` stays in `app.css`. It is the scheme *mechanism* (WP84's constraint),
not a token, so a theme cannot opt out of dark mode, only restyle it.

### The chevrons are one theme's furniture

As the entry required, the connectors are an `::after` on `.step-nav__entry` with a
`clip-path` V. Their size comes from `--nav-chevron-size` and their colour from
`--nav-chevron-color`. Classic sets the size to `0px`, so they draw nothing. They sit at `top: 100%`
of an entry, which is exactly on the next entry's top rule, so they read as the rule bending down.
They are suppressed structurally in the narrow layout, where the nav is a wrapping row with no
"next step below".

### Live switch by an out-of-band `<link>`, and preferences are not chargen changes

The route answers with just the new `<link id="theme-stylesheet" hx-swap-oob="true">`, and htmx
swaps it inside `<head>` in place. I verified in Chromium, in both schemes, that the computed
background changes with no reload and that the link keeps its order ahead of `app.css`.

Without the middleware exclusion, a theme change would have fired `chargen-changed` and made the
nav, panel, and tab strip all re-fetch for nothing. `/ui/prefs/` is now the documented home for
display preferences, and WP101's language picker should go there too. It needs `HX-Refresh`
instead of an out-of-band swap, because every string changes.

### Session-scoped, not persisted

The entry says "a theme preference on `ChargenSession`", and that is what shipped. It lasts as long
as the in-memory session, which is the same lifetime as everything else the app holds. It is never
written to a save: a theme is not part of a character.

## Traps hit

- **The frame token touches Classic's look slightly.** Classic's sidebar now carries the shared
  1px frame on its left and top edges too, where it used to have only a right border. Visually that
  is one hairline at the window's left edge. Giving each edge its own token to preserve it exactly
  did not seem worth three more tokens per theme.
- **`.panel` border-radius.** My first pass routed `--radius` onto `.panel` as well. On a panel with
  a 4px left accent that rounds the accent bar oddly, and panels never had a radius, so `--radius`
  stays on the status boxes only.
