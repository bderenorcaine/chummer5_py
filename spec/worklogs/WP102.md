# WP102 — Route every chrome string through the key layer

Phase W's sixth WP is the mechanical conversion pass that WP101's machinery was built for. Every
piece of user-facing chrome text in the web layer now comes from a catalog key, in all 22 templates
and every route module. Tests now enforce that, so the next WP cannot quietly erode it. English
output is unchanged except where noted under Decisions.

## What landed

- **Catalog.** `src/chummer5/lang/en-us.xml` grew from 4 to 327 `Web_*` keys, grouped by area. The
  templates also reuse about 30 legacy keys (`String_Karma`, `Tab_Skills`, `Label_Attributes`,
  `String_Attribute<CODE>Short`, …).
- **Templates.** All 22 are converted. Each placeholder, heading, table header, help paragraph,
  button, `title`, `placeholder`, and `aria-label` goes through `_()` or `_n()`.
- **Python.** The shell's `StepPage`/`PageSection` fields became `label_key`,
  `unavailable_reason_key`, `disabled_reason_key`, `heading_key`, and `locked_note_key`, and the
  resource panel rows gained `label_key`. The following now return `Message`s:
  - the ten "No longer fits" budget warnings;
  - lifestyle's itemised warning;
  - the three priorities errors;
  - the load/import messages;
  - the Matrix stat block.

  The sheet's conditional-limit labels are keys.
- **`chummer5.web.i18n`** gained:
  - `Message`/`MessageJoin` and `render_message`, exposed as the `| tr` filter;
  - `translate_plural`/`plural_key`, exposed as `_n()`;
  - `format_nuyen`, exposed as `| nuyen`;
  - a Markup-aware template `_()` (`_markup_format`).
- **`src/chummer5/lang/README.md`** gained rules 6-9: plurals, money, computed keys, and
  `Message`.
- **Tests:**
  - `tests/unit/test_web_no_bare_text.py` (new, 4 tests) covers templates, template scripts, and
    an AST scan of web-layer Python. The Python scan has a self-test.
  - `tests/unit/test_web_i18n.py` gained 11 tests: computed-key families, shell-table keys,
    `Message`/`MessageJoin`, Markup arguments, plurals, the one-money-formatter rule, and a render
    of every page and tab for Mundane, Magician, and Adept asserting no `⟦Key⟧` marker and no i18n
    warning.

## Decisions

### Build the enforcement first, and use it as the worklist

The phase file calls this "the WP most likely to be quietly half-done", so I wrote the
template scanner before converting anything. It strips Jinja expressions, tags, comments, and
script bodies, then flags any surviving letter in a text node or a user-facing attribute. It
reported 334 runs, and the pass was done when it reported zero. The same approach, as an AST scan,
inventoried the Python side at about 30 real strings. The phase file's "~470 + ~65" estimate
counted more generously; nothing was skipped to reach the lower number.

### `Message` instead of threading a locale

Step context builders take a `Character`, not a session, and there are about fifteen of them.
Passing a locale through every one, and through `chargen_context`'s fifteen calls, would have
touched every builder's signature for a presentation concern. A builder returns a `Message(key,
params)` instead, and the template translates it with `| tr`. `| tr` also accepts a plain `str`,
which is what an engine `ValueError`'s text is. Every `*_error`/`*_budget_warning`/`sheet_*`
display got the filter: 28 sites, all changed by one `sed`.

### Lifestyle's warning was assembled English

It built `"gear (X) + lifestyle (Y) + …"` by joining f-strings. That is exactly the "concatenate
two keys" failure the phase file warns about, but worse, since the parts were not keys at all. It
is now one keyed sentence with a `{breakdown}` parameter. The breakdown is a `MessageJoin` of
per-spender keys, joined by the keyed separator `Web_List_Plus`. The existing test's
`"gear (43500) + lifestyle (10000)"` assertion still passes unchanged.

### Inline markup without markup in the catalog

The cyberware help text emphasises one word (`<strong>Capacity</strong>`). The template-side `_()`
now escapes the catalog text and `Markup.format`s its arguments, so the template builds the
`<strong>` itself (`{% set capacity_word %}…{% endset %}`) and passes it as a parameter. The
catalog holds `…costs the parent's {capacity} and nuyen…`. For every call without `Markup`
arguments, the output is byte-identical to plain autoescaping.

### Deliberate English changes

- Legacy's Title Case for the panel and tab labels ("Attribute Points", "Adept Powers", "Vehicles
  & Drones", "Free Spells"), so they reuse legacy keys that already carry real translations. I
  updated my WP98/99 tests to match.
- Build method: the raw codename `SumtoTen` now reads "Sum-to-Ten".
- `Magic x 2 --` became `Magic × 2 —`, and `Magic Rating x2` became `Magic Rating × 2`.
- The Karma-conversion label's grouped `2,000¥` is now `2000¥`, from the `nuyen` formatter and the
  engine's own `KARMA_TO_NUYEN_RATE`. It matches every other amount in the app.
- The sheet's placeholder said "the chargen page", a pre-WP97 phrase; it now says "the Priorities
  page" like every other step.

### Out of scope, recorded rather than silently skipped

- **Engine messages.** Every "No longer fits" warning embeds an engine `ValueError`'s text, and
  step errors show engine text directly. Translating them means message keys in the rules layer.
  That is a project in itself, outside a web-layer WP.
- **English in `chummer5.data` modules.** `CONDITION_DESCRIPTIONS` (the sheet's "— while making a
  visual Perception test"), the unmodeled-effect notes, and `chummer5.data.knowledge`'s categories,
  examples, and suggested languages are project-authored English, not legacy XML. So WP103's
  `_data.xml` lookup will not reach them, and they are not chrome either. They are logged in the
  decisions log as a third category.
- **Digit grouping.** Identified and centralised in `format_nuyen`, and left ungrouped.

## Traps hit

- **Vacuous assertions, again.** Joining the priorities intro onto one catalog line made
  `"different priority letter"` appear on every priorities render, so three positive tests went
  vacuous and one negative test failed. All four now target the error's own wording ("must each use
  a different priority letter"). The Powers tab label now reads "Adept Powers", which broke a
  Mundane test's `"Adept Powers" not in page`. I re-pointed it at the fragment's heading, as WP97
  did for its siblings. **Pre-existing and left alone:** `test_web_attribute_skill_allocation.py:225`'s `"strict skill
  groups" in response.text` was already satisfied by the help paragraph before WP102.
- **A computed key looks like a literal.** `_("Web_BuildMethod_" ~ method)` made WP101's
  literal-key test look up `Web_BuildMethod_`. The regex now requires the quoted key to be the
  whole argument, and computed families have their own test.
- **An import inserted mid-block.** My scripted `import Message` insertion landed inside three
  multi-line `from … import (` blocks. That caused 23 collection errors, fixed immediately.

## Verification

- `pytest` 1418 passed (1404 before WP102's new tests, plus 14 new). `ruff check`/`ruff format
  --check` clean; `mypy src` clean.
- The scanners report zero offenders. Mutation checks:
  - dropping one key from the catalog fails both the literal-key test and all three per-archetype
    render tests;
  - the Python scanner's self-test proves it flags an f-string and a sentence literal while
    skipping docstrings and dict keys.
- A Playwright walk over all 12 pages and tabs found no `⟦` marker and no console errors. The
  window title renders as "Chummer5 — Priorities".
