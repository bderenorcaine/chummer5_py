# WP103 — Game-data term translation in the loaders

Phase W's last WP. Chrome strings went through keys in WP101/102. This WP covers the other half of
the page: skill, quality, metatype, gear, spell, lifestyle, and priority-row names, their
categories, and the mentor texts. They are translated at display time from the legacy
`<locale>_data.xml` files, and never used as identity.

## What landed

- **`chummer5.data.lang.load_data_terms(locale)`** builds a `DataTerms` index over
  `legacy/Chummer/lang/<locale>_data.xml` with three lookups:
  - `by_id`: GUID → {English name: translation};
  - `by_file`: data file → {English text: translation}, which covers item names, categories,
    skill groups, and anything `translate="…"`-attributed;
  - `fields`: (GUID, field) → a translated long text, from `<altadvantage>`/`<altdisadvantage>`/….

  `en-us` has no such file, since English *is* the data, and gets `EMPTY_DATA_TERMS`. Loading
  German takes about 0.04 s and indexes 7,184 ids.
- **`chummer5.web.i18n`**:
  - `DATA_TERMS` is a lazy per-locale cache, stub-able like `CATALOGS`.
  - `data_term(locale, value, *files)` accepts an object, a context row, or a string.
  - `data_text(locale, value, field)` looks up long texts.
  - The `| dterm("file.xml", …)` and `| dtext("field")` filters are registered in `catalogs.py`.
- **Templates:** every game-data *display* site in all 22 templates goes through `dterm`/`dtext`.
  That covers priority rows, metatypes, talent options, traditions, skills and groups and
  categories, knowledge categories, suggested languages, qualities and their categories, mentor
  names/choices/advantage/disadvantage, spells, powers, spirit types, foci, gear, lifestyle tiers,
  cyberware/bioware (including bundled names and plugins), vehicles, and every such name on the
  character sheet.
- **`routes/character.py`**: `priority_summary` passes `(letter, name)` instead of a pre-joined
  English string, and the sheet reuses the priority form's summary keys, which retired five
  `Web_Sheet_Priority*` keys. Bioware rows tally by `(name, chosen skill)` instead of a pre-joined
  `"Name (Skill)"` label.
- **Tests:**
  - `tests/unit/test_web_data_terms.py` (7 tests) runs against the real de-de catalog.
  - `test_web_i18n.py` gained `test_no_project_key_is_an_orphan`.

## Decisions

### Display only, never identity, enforced by a round trip

The phase file names the trap: any translated name reaching an id, a form value, or a save makes
saves locale-dependent. So `dterm` is applied only to visible text, and never to:
- `value=` attributes;
- field `name=`s, including name-keyed starter gear (`name="gear_Medkit"`) and lifestyle tiers
  (`value="Low"`);
- `data-details-key`.

The acceptance test builds a character under German: a quality, a skill, a lifestyle, and gear. It
saves, loads the save into a fresh English session, and saves again. The two saves are **equal**,
and none of the German names that were on screen appear in the save.

### Lookup by GUID, checked against the name

The phase file expected lookup "keyed by the English name". Our catalogs carry the legacy GUIDs, so
by id seemed strictly better. Then the first German test showed "Handfeuerwaffen" for Pistols. The
German file puts the Pistols skill's GUID on two entries: "Pistols" → "Pistolen" and an alternate
"Handguns" → "Handfeuerwaffen". A last-wins id map took the wrong one. I measured the pattern
across the five locales: de-de has 26 such ids, and fr/ja/pt/zh have 4-5 each.

So `by_id` keeps each GUID's entries by English name. A lookup takes the entry matching the
object's name, takes the sole entry when there is only one (a translation file one rename behind
still works), and otherwise falls back to the name in the given files. That fallback also serves
the four catalogs that have no id: lifestyle tiers, starter gear, talent options, and priority
rows.

A second collision is *within* a file. skills.xml's `<spec translate="…">` specialisations reuse
English skill names, so an item's own `<name>/<translate>` pair overwrites, while
attribute-translated texts only `setdefault`.

### Filter scripts match what the player sees

The skill and gear filter scripts compare the typed query against `data-skill-name` and
`data-gear-name`/`-category`. Those now carry the lower-cased *display* name. A German player
types "pistolen", not "pistols". This is the one place a translated string enters an attribute,
and it is a display-matching attribute, not an identity.

### What stays English, recorded

- **Project-authored English in `chummer5.data` modules** has no legacy translation: knowledge
  categories' *examples*, `CONDITION_DESCRIPTIONS`, and the unmodeled-effect notes. The category
  *names* and suggested languages do translate, because skills.xml carries them.
- **Engine exception texts** (WP102's decision).
- **Sort order.** Lists are sorted by English name, so German lists are not alphabetical.
  This is identified, not solved.
- **Spell descriptors** (type/range/duration codes such as `P`, `LOS`, `S`) are codes, shown as-is.

### Still English-only in the picker

The mechanism covers all five legacy locales, but German chrome would be mostly English fallback:
the 327 `Web_*` keys are English-only. Offering German is now a translation task plus one line in
`prefs.LOCALES`, not engineering. The tests offer de-de by monkeypatching `prefs`.

## Traps hit

- **A wrong test expectation encoded the GUID bug.** I wrote the first German assertions from the
  loader's own probe output ("Pistols → Handfeuerwaffen"), so the bug looked like the spec for
  one run. The name-collision tests exposed it. Worth remembering: never derive an expected value
  from the code under test.
- **Specs shadowing skills** in the per-file map; see above.

## Verification

- `pytest` 1426 passed (8 new). `ruff check`/`ruff format --check` clean; `mypy src` clean.
- Every English assertion in the existing suite passed unchanged, because `dterm` returns the
  English name when the locale is `en-us`.
- Against the real de-de catalog:
  - the skills page shows `<td>Pistolen</td>` and `Kampf-Aktionsfertigkeiten`, with
    `name="skill_<GUID>"` unchanged;
  - the priorities page shows "A - Jeder Metatyp" and "Mensch";
  - the lifestyle select shows "Unterschicht" with `value="Low"`;
  - the sheet shows all of these;
  - the round trip holds.
- No rulebook lookup was needed (the WP is about the legacy translation files, not rules), so there
  is no learnings entry.
