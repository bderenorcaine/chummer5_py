# WP104 — A Shadowrun theme, made the default

Added to Phase W on 2026-09-26. The request was a theme that imitates the look and feel of the SR5
core rulebook, with a scan of p. 48 ("Extended Tests") as the reference, and to make that theme
the default. It ships as `static/themes/shadowrun.css`, listed first in the picker, and a new
session opens in it.

## What the reference page is made of

These are the pieces of the page that a character generator can reasonably borrow:

- **Red banners.** Dark-red boxes with a vertical gradient carry gold condensed capitals ("A NOTE
  ON ROUNDING", the notation box). Their corners are cut off diagonally.
- **White boxes.** The "EXAMPLE" box has a heavy black outline and chamfered top-left and
  bottom-right corners.
- **Black tables.** Tables sit in near-black boxes, with gold column heads over a gold rule and
  alternating grey rows.
- **Section heads.** Headings are squared "techno" capitals, widely spaced, in black over a thin
  rule ("EXTENDED TESTS").
- **The page.** The body text is black on a pale grey ground with faint horizontal scan lines. A
  dark red-black band runs across the top.

## How it maps onto the shell

| Book | Shell |
|---|---|
| Top band | Title bar: red-black vertical gradient, title in spaced capitals |
| Black table box | Sidebar: charcoal gradient with light nav items. The current step is a red gradient with a gold accent and gold text. "Remaining" is in gold capitals. |
| Red banner | `.page__heading` (the Export page's heading): red gradient, gold capitals, chamfered top-right and bottom-left corners |
| "EXAMPLE" box | `.panel`: white, with 3px black top and left rules, chamfered top-left and bottom-right corners, and a drawn diagonal along the top-left cut |
| Table heads | `.page thead th`: gold on near-black |
| Section heads | `.panel__heading`: spaced capitals over the existing rule |
| Page ground | `--main-bg`: 1px scan lines every 4px over a pale grey gradient |

Status boxes follow the book's sidebars as well. `.error` is a red banner with pale text.
`.warning` is a black box with gold text. That choice also solves a constraint: `--warning-fg` is
the nav's staleness-marker colour too, and it now has to be legible on the dark sidebar and in the
warning box. Gold on black works in both places, and amber on pale yellow would not.

In dark mode the page and panels become charcoal, panel headings turn gold, and the red and gold
furniture stays the same.

## Decisions

### Tokens, not a theme-specific selector

WP100's contract says a theme is custom-property declarations only. The book needs *shapes*, and
the 51 existing tokens only covered colour, fonts and rule weights. So `app.css` gained 11 tokens,
each wired into exactly the rule that needs it:

- `--display-transform` and `--display-letter-spacing`, for the title, nav items, tabs, the page
  heading, panel headings and the resource heading. They are one pair rather than one per element,
  because the book spaces every display face the same way.
- `--page-heading-fg`, `-bg`, `-padding` and `-clip`, for the banner.
- `--panel-clip`, for the chamfer.
- `--sidebar-fg` and `--sidebar-heading-fg`. Before this WP the sidebar inherited `--page-fg`, and
  the resource heading used `--summary-fg`. Both are dark-on-dark once the sidebar is black while
  the page stays light.
- `--table-head-fg` and `--table-head-bg`.

Classic and Sketch get neutral values: `none`, `normal`, `0`, `transparent`, `currentcolor`, and
`var(--page-fg)`/`var(--summary-fg)` for the colours that used to be implicit. Because those
values reference existing tokens, they follow each theme's dark block automatically, and neither
theme needed a dark-block addition.

### The diagonal lives in the panel's background token

`clip-path` cuts the border along with the box, so the first render showed a gap at the top-left
corner where the book draws a diagonal rule. The SR5 theme's `--section-bg-a`/`-b` are therefore
two-layer `background` values: a 135° linear gradient that draws a 3.5px line across a 1rem×1rem
square at `border-box` origin, and then the fill colour. This is legal because `app.css` only uses
those two tokens in `background`. The decisions log records the trap: a future `color:` use of them
would break this theme. The bottom-right cut gets no drawn diagonal, because panels have no right
border for it to join.

### Fonts: named, not vendored

The book's faces are commercial. The stacks name them first (Eurostile/Microgramma for heads,
Myriad for body), then free look-alikes a player may have installed (Michroma/Orbitron and Bebas
Neue/Oswald/Roboto Condensed), then system fallbacks (DejaVu Sans, Arial Narrow/Liberation Sans
Narrow). I did not vendor a webfont. It would be the project's first binary static asset besides
htmx, and I could not download one from this environment anyway. On a bare Linux box the look
therefore rests on the capitals, spacing and colours, and it still reads as the book. Vendoring
Michroma plus Oswald (both OFL) is the obvious follow-up if the fallback faces disappoint.

### Default and picker order

`DEFAULT_THEME = "shadowrun"`, and the theme is first in `THEMES`, so the picker lists the default
first. The WP100 tests were already written against `DEFAULT_THEME` rather than `"classic"`. One
new test pins the default and the ordering.

## Verification

- `pytest`: 1429 passed. That count includes the WP100 parametrized theme tests, which now run for
  three themes, plus 1 new test. `ruff check`, `ruff format --check` and `mypy src` are clean.
- Headless Chromium screenshots in both schemes, compared against the reference:
  - Priorities, Attributes and Skills pages, with a confirmed Human A/E/B/C/D character;
  - the Export page, for the banner heading and the table heads.
- **Classic and Sketch are unchanged, pixel for pixel.** I ran a second server from a `HEAD`
  worktree and rendered Attributes and Export under both themes in both schemes from both servers.
  I removed the one markup difference, the new `<option>` in the theme picker, which widens the
  `<select>`. The screenshots were then byte-identical.
