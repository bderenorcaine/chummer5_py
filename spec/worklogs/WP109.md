# WP109 — Derived-stat foundations: Overflow, wound-modifier interval, Armor, Damage Resistance

The third Phase X foundation. Several qualities, powers and implants later in the phase need a
character-level number that didn't exist yet. The phase file calls them Finding 6: an Armor total,
Overflow boxes, a wound-modifier interval and a Damage Resistance pool. This WP builds all four once,
each with an Improvement type later WPs can target, and puts them on the character sheet.

## What landed

- **Six `ImprovementType`s**: `CM_OVERFLOW`, `CM_THRESHOLD`, `CM_THRESHOLD_OFFSET`,
  `CM_SHARED_THRESHOLD_OFFSET`, `ARMOR`, `DAMAGE_RESISTANCE`. They are named after their legacy
  counterparts and mirror the data's `<conditionmonitor>` children.
- **`chummer5.engine.derived`**: `overflow`, `wound_modifier_rule` (a `WoundModifierRule` with
  boxes-per-modifier and ignored boxes per track), `armor_breakdown` / `armor`, and
  `damage_resistance`.
- **The three `+N` armor accessories are offered.** Helmet, Ballistic Shield and Riot Shield were
  excluded by WP21. `StarterGearItem.armor_stacks` marks them, and they add to the worn body armor,
  capped at Strength.
- **A "worn" flag.** `Character.unworn_armor` is the set of names the player has unticked.
  Everything bought is worn by default. Each owned armor row on the Gear page has an "Equipped"
  checkbox. The set is saved as `unworn_armor`, an additive field with no version bump.
- **Cyberware armor is computed.** `classify_bonus` recognises bare `<armor>` and
  `<damageresistance>` leaves (a literal or `Rating`), and reads `group="N"` as the dedup group
  `groupN`. That makes Bone Lacing ×3, Dermal Plating and the cyberlimb Armor enhancement
  `FLAT_BONUS`. Bone Lacing's unarmed-DV children are stripped as
  `REGISTERED_UNMODELED_BONUS_TAGS`, which is only allowed because every row carrying one has a note,
  and a test pins that.
- **Registry**: Dermal Plating's row is gone because it's fully modeled. Bone Lacing and the Armor
  enhancement shrink to their remainders: the unarmed DV and the per-limb cap. `test_augmentation_
  unmodeled_registry.py` moves them from "registered" to "partly modeled with notes", and the
  NOT_YET_SUPPORTED cyberware count goes from 10 to 5.
- **Character sheet**: Overflow, Wound modifiers, Armor (with a breakdown and any encumbrance note),
  and Damage Resistance rows.

## Decisions

### No legacy "+1" Overflow box

Legacy `CMOverflow` is `BOD.TotalValue + CMOverflow + 1`, and its comment says the extra box marks
the character as dead. The rulebook's Final Calculations examples give James Overflow 3 at Body 3,
so the box is a record-sheet convention and is left out. Legacy does use *augmented* Body, and so
does this.

### The shared threshold offset is reported whole on both tracks

Legacy splits `CMSharedThresholdOffset` between Physical and Stun by how much damage each has taken.
At creation nothing is damaged, so both tracks get all of it. The sheet shows one "first N boxes
ignored" figure, because both tracks are identical until damage is tracked, which this project never
does.

### The accessory encumbrance penalty is shown, not applied

p. 169's −1 Agility and Reaction per 2 points over Strength applies "while trying to use" the gear.
Subtracting it from the attributes would ripple into every dice pool and limit on the sheet for a
state that is really situational. So `ArmorBreakdown.encumbrance_penalty` is a sheet note. The
Strength cap on the Armor number itself is applied, because that is what the number means.

### The worn flag lives on `Character`, not in `ResourcesSelection`

`create_resources_selection` is re-run from many carry-forward sites (priorities, lifestyle,
cyberware and bioware edits re-validating the shared budget). Threading a worn set through every one
would have been a large diff for a value no budget check reads. A separate name set on `Character`
touches one route. The route uses a hidden `armor_shown` marker per rendered checkbox, so an
unticked box can be told apart from an item that wasn't on the page yet. An item bought in the same
submission therefore starts worn.

### The Damage Resistance pool includes Bone Lacing's Body dice unconditionally

The printed boost is "for resisting physical damage". The sheet has one pool, as legacy's
`DamageResistancePool` does, and the Physical-only caveat is in the row's note. Splitting the pool
into Physical and Stun is not worth it for one item.

## Traps hit

- The web test first expected "Helmet +2". A fresh Human in the web tests has STR 1, so the cap
  made it +1. The engine was right and the test wasn't.
- `build_character`'s `cyberware` catalog defaults to `()`, so a unit test built through the save
  path has to pass `load_cyberware_entries()` explicitly.
- Five pinned counts in three test files (`test_cyberware.py`, `test_cyberware_subsystems.py`, the
  registry test) moved together. Each now says WP109 moved it.
