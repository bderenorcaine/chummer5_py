# WP110 — Reputation: Street Cred, Notoriety, Public Awareness

Step Eight's Reputation row, per the phase file's Finding 3.

## What landed

- **`Quality.notoriety`** in `chummer5.data.qualities`: the `<bonus><notoriety>` value, parsed
  independently of `bonus_support`, plus `_NOTORIETY_OVERRIDES = {"Gremlins": 1}` for the one
  listed quality whose row has no `<bonus>`. A test pins that exactly the p. 368 list (plus Bad Rep)
  carries a shift.
- **`ImprovementType.NOTORIETY`**. `apply_quality_improvements` adds one for any quality with a
  shift, in a dedup group per listed quality, so every Addiction severity and every repeated
  instance counts once.
- **`chummer5.engine.derived.street_cred` / `notoriety` / `public_awareness`**. Street Cred and Public
  Awareness are 0 at creation, and their docstrings cite why. Notoriety may go negative, for example
  with Blandness and Lucky.
- **Character sheet**: Street Cred, Notoriety and Public Awareness rows.
- **Registry**: SINner (Criminal)'s row loses its "unmodeled Notoriety point" clause, in both the
  Project Overview and `_UNMODELED_EFFECT_NOTES`.

## Decisions

### `<notoriety>` doesn't change how a quality classifies

If `_classify_bonus` recognised `<notoriety>`, Bad Luck, Combat Paralysis and the other qualities
whose only `<bonus>` content it is would become `FLAT_BONUS`, and so *offerable*, in this WP, with
no registry note for the rest of their effect. That breaks the phase's own convention. WP114/WP115
offer them with their notes. So the value is read into its own field, and the classifier still
treats the tag as unsupported.

### Two Addictions count once

The phase file asked. p. 368 names "Addiction" and not its severities, and says a character "cannot
earn a Notoriety point for something for which they have already received a point". Legacy sums
per instance, and the rulebook wins. The dedup rides on `Improvement.unique_name`: every
improvement in the group is worth +1, so highest-wins keeps exactly one.

### Street Cred is 0, not Karma ÷ 10

The creation Karma pool is *spent*, not *earned*. Legacy's `CalculatedStreetCred` reads career Karma
only. Public Awareness likewise ignores legacy's optional "(SC + N) / 3" setting, which is off by
default and not in the book.
