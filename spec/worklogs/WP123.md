# WP123 — Karma-funded Magic increases

Step Seven Karma can now raise Magic for a Magician, an Adept or an Aspected Magician, at
`new Rating × 5` (p. 106).

## Research (the plan asked for it first)

p. 278 answers both questions; see the learnings entry.

- Essence loss lowers the current rating *and* the maximum.
- A Karma raise starts from the reduced current rating and is capped by the reduced maximum. The
  book's own example (Magic 4, max 6, a 0.2-Essence cybereye) gives 3 with a maximum of 5, and
  raising that 3 to 5 costs 45 Karma.

## What landed

- **Engine** (`engine/character.py`):
  - `create_karma_attribute_points` accepts "MAG" when the character is Awakened, and prices it
    through `_karma_magic_cost`. That function starts from `magic_before_karma()`, rejects a raise
    past the reduced maximum, and rejects any raise after burnout.
  - `magic_rating_before_essence_loss` adds the Karma points, so `attribute_value("MAG")` and
    `power_points` follow.
- **Web**: the attributes page's MAG row has a Karma input (`karma_attr_MAG`). The submit route
  parses it for a magic user. The preview cost prices it from the current rating. Both the submit
  and the stale re-check validate against *this submission's* Special-Attribute MAG points. Before
  this WP they used the previous ones, which didn't matter while MAG had no Karma path.
- **Save**: no change. `karma_attribute_points` is a generic map, and the loader already builds the
  Karma selection after the magic fields.
- The `KarmaAttributeSelection` docstring's "deliberately excludes MAG" paragraph is replaced.

## Decisions

- Exceptional Attribute (MAG) is respected through `attribute_maximum("MAG")`, as WP112 set up.
- Legacy import still blocks a legacy MAG Karma spend; see the decisions log.
