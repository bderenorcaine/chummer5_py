# WP124 — Exotic skills per specific weapon or vehicle

Exotic Melee Weapon, Exotic Ranged Weapon and Pilot Exotic Vehicle are now bought once per named
item, as separate skills (p. 131, p. 147). Before this WP each was a single catalog skill with one
rating.

## Research

p. 131 and p. 147 say "must be taken once for each" item, and list "Specializations: None" / "N/A".
Exotic Melee Weapon has no entry of its own in the core Skills chapter. See the learnings entry.

## Design: a compound key, not a tuple key

The plan's deliverable says "allocation keys become `(skill_id, specific)`". A literal tuple key
would have changed the shape of `skill_points`, `karma_skill_points`, the save format's JSON maps,
the web form's field names and every `skills_by_id[...]` lookup. Instead, an instance is keyed
`"{skill_id}|{specific}"` (`engine.skills.exotic_skill_key` / `split_skill_key`), inside the
existing string-keyed maps.

The engine turns each such key into a synthetic `Skill` (`exotic_instance`): the catalog entry with
`id` set to the compound key and the new `Skill.specific` field set. It keeps the catalog `name`.
So `natural_skill_rating`, `skill_rating` and `dice_pool`, which all read by `skill.id`, work
unchanged. So do Improvements that name the skill (Aptitude, Critical Strike, a Reflex Recorder's
chosen skill), which reach every instance of it.

## What landed

- **Data**: `Skill.specific` (default `None`).
- **Engine** (`engine/skills.py`):
  - `exotic_skill_key`, `split_skill_key`, `exotic_instance`, `exotic_instances`,
    `with_exotic_instances`, `character_skills` and `bought_skill_keys`.
  - `create_skill_allocation` and `create_karma_skill_selection` expand the catalog with the
    submitted instances before validating. They reject a bare exotic catalog id ("needs one named"),
    a blank item, an item on a non-exotic skill, and any specialization on an exotic skill.
    `skill_points_spent` expands too.
- **Save** (`io/save_format.py`): no field and no version bump, since the maps keep their shape.
  `build_character` moves a pre-WP124 bare exotic spend onto an `Unspecified` instance and drops an
  exotic specialization (`migrate_bare_exotic_keys`, `drop_exotic_specializations`).
- **Legacy import**: `LegacySkill.specific` reads `<specific>`. `_skill_key` keys an exotic skill by
  it, falling back to `Unspecified`. An exotic skill's specialization is dropped and reported.
- **Web**:
  - The skills page no longer shows an exotic catalog row. Each bought instance gets a row in its
    category, with a hidden `exotic_key` input and "—" in both specialization columns.
  - A new "Exotic skills" table adds one: skill, item, points, Karma points. A half-filled row
    (no item, or no points) is echoed back and never lost. A duplicate is refused with
    `Web_Skills_ExoticDuplicate`. Setting an instance to 0 removes it.
  - The sheet lists instances as "Exotic Ranged Weapon (Flamethrower)".
  - Five new `Web_Skills_Exotic*` strings.

## Decisions

- **The item is free text.** The core book lists examples, not a closed list, as with
  specializations.
- **"Unspecified" for old data.** A pre-WP124 save or a legacy file with no `<specific>` bought
  the skill without a named item. The spend is kept on a clearly-labeled instance rather than
  dropped or invented. The player can zero it and add a named one.
- **Instances share the catalog name.** An Improvement naming "Exotic Ranged Weapon" applies to
  every instance. The core book has no per-item Improvement, so there is nothing to lose. Name-keyed
  maps built over the plain catalog (`later_step_facts`, the Talent skill-rating map) still see only
  the catalog entry, at 0. Loss of Confidence on an exotic skill therefore can't be taken, which is
  an acceptable edge.

## Traps

- The skill-name `<td>` has to stay on one line. Two existing tests assert on `<td>Pistolen</td>`
  and `<td>Ritual Spellcasting</td>`.
- The add row must only be cleared once it's actually bought. Otherwise a successful submission of
  some other field wipes the item the player has just typed.
