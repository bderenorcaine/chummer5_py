# WP127 — Implant grades: Standard, Alphaware, Used

Every cyberware and bioware purchase now carries a grade. The grade scales its Essence and nuyen
cost and shifts its Availability, per p. 451's table. Plugins inherit their parent's grade.

## Research

See the learnings entry for the p. 451 quote and table. The legacy engine was re-read for two
things:

- **Cost.** It multiplies the cost by the grade and keeps the decimal.
- **Essence.** It puts the grade's multiplier on the additive Essence stack. This project has no
  other additive Essence modifier, so the product is the same.

## What landed

- **Data** (`data/grades.py`, new): `ImplantGrade` (multipliers, the Availability modifier, and
  `nuyen()` with half-up rounding). The three creation grades are parsed once from `cyberware.xml`.
  `implant_grade(name)` rejects any other grade.
- **Engine, cyberware** (`engine/cyberware_subsystems.py`):
  - `CyberwarePurchaseRequest.grade` and `PurchasedCyberware.grade`.
  - `_build_purchase` applies the grade to nuyen and Essence. Plugins and bundled subsystems get
    their parent's grade.
  - `grade_offered` / `offered_grades` implement the fixed over-cap item rule (Standard only).
  - `availability_capped_maximum(..., grade)` applies the Availability shift.
  - The exempt set is now `(id, rating, grade)`.
  - `to_requests` round-trips the grade.
- **Engine, bioware** (`engine/bioware.py`):
  - `BiowarePurchaseRequest.grade`.
  - `BiowarePurchase.grade`, plus `nuyen_cost` / `essence_cost` properties that the totals and the
    Essence Improvement now read.
  - `bioware_grade_offered`, and `purchased_grades` feeding `create_bioware_selection`'s new
    `availability_exempt`.
- **Save**: a `grade` key on each cyberware node and bioware purchase. It is additive and reads as
  Standard when absent, with no version bump.
- **Legacy import**:
  - The three creation grades import, carried on the requests.
  - Any other grade gets its own reason ("Betaware grade is not available at character creation").
  - Catalog misses keep a reason that no longer mentions grade.
- **Web**:
  - A Grade select on each bought cyberware unit, and per bought bioware unit.
  - Graded unit, plugin and bioware prices, and the graded Essence tally.
  - The rating dropdown follows the grade's cap.
  - The sheet shows "[Alphaware]" / "[Used]", and groups by grade.
  - Two new strings.

## Decisions

Rounding, the cap interaction, and legacy import are in the decisions log. Also:

- **One grade table for both catalogs.** The bioware file's rows are numerically identical, and
  only `<devicerating>` differs, which nothing here reads.
- **A plugin request's own grade is ignored rather than rejected.** The UI never sends one, and a
  save writes the parent's grade onto each plugin node for readability.

## Traps

- **Exact-shape save tests.** Two save-format tests assert the literal JSON of a purchase node.
  They gained the `grade` key.
- **Five import tests encoded the old rule.** Their expectations moved to the new one:
  - Used limbs now resolve.
  - Barrett's arm itemizes 4 non-SR5 children instead of 7 nodes.
  - The "non-Standard" reason text changed.
  - The rejection test now uses Betaware, with an Alphaware / Used positive test beside it.
- **The unit legacy-import tests pass an empty catalog by default.** A positive grade test needs
  `cyberware=CYBERWARE` / `bioware=BIOWARE`, or it fails as a "catalog miss" that looks like a
  grade bug.
