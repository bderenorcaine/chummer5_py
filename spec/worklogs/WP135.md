# WP135 — Character validation: the rulebook's closing checklist

One validator now reports every whole-character rule. The Export page lists the issues by step,
with links. The nav marks every step that has one, and the title bar shows "✓ Complete" or
"N issues". Nothing is ever blocked. This closes Phase X.

## Research

See the learnings entry: p. 66's "must spend all attribute points" and "Special Attribute points
disappear", p. 71's 25-Karma quality caps, and the earlier WPs' p. 69 magic rules. The plan's clean
example, James, is a Technomancer. This project doesn't build those, so the complete synthetic rigger
build stands in.

## What landed

- **Engine** (`engine/validation.py`):
  - `SessionLetters` (the five letters and the build method).
  - `Issue`: severity, step slug, optional tab, i18n key, and parameters.
  - `validate()`, whose checks are:
    - priority rows used once, or a Sum-to-Ten total of 10;
    - attribute, special, skill and group points (unspent is a warning, overspent an error that
      names the pool);
    - free Knowledge points unspent;
    - two or more attributes at natural maximum;
    - the 25-Karma quality caps;
    - the later-step quality prerequisites (Loss of Confidence, Scorched), via the new public
      `qualities.later_step_problem`;
    - an Aspected Magician Incompetent in a group it can never learn;
    - an Adept's free grant naming Assensing without Astral Perception;
    - no Lifestyle, and nuyen overspent;
    - no contacts;
    - Karma negative.
- **Web**:
  - `shell.validation_issues()` combines the engine's issues with every section's WP19 warning (as
    errors, in step order). `issue_message()` translates `*_key` parameters, and
    `validation_context()` groups issues for the page and counts them for the title bar.
  - `nav_context` marks a page with any issue.
  - `GET /ui/validation-status` and `_validation_status.html` go in the title bar and re-fetch
    themselves on `chargen-changed`.
  - The Export page's "Character checklist" panel groups issues by step, and each one links to
    its page and tab. It shows "✓ Every creation rule is met" when there are none.
    `_character_sheet_context` takes an optional `chargen_ctx`, so the Export page doesn't compute
    it twice.
  - 24 new strings. The nav marker's tooltip is reworded to "has issues".
- **Tests changed**:
  - `test_web_i18n`'s orphan check also scans `engine/validation.py`, which names its keys.
  - `test_web_shell`'s WP19 nav test checks the checklist text, since unspent points now mark
    steps too.

## Traps

- **Synthetic mundane fixtures leave `talent_letter` as `None`.** A test's `SessionLetters` must
  fill in the unused letter. For Sum-to-Ten that can't be guessed, so only the Priority-built
  rigger is used.
- **Not every attribute has a key in `attribute_points`.** Unspent ones are simply absent.
- **The character sheet has more than one `</section>`.** Tests slice the panel from its own id.
