# WP136 — Storage layer

`chummer5.store` is the headless persistence module the rest of Phase Y builds on: stdlib
`sqlite3`, no web imports.

## What landed

- `config.py`: `CHUMMER5_DB` (default `$XDG_DATA_HOME` or `~/.local/share`, `/chummer5/chummer5.db`)
  and `CHUMMER5_CHARACTER_QUOTA` (default 100).
- `migrations.py`: an ordered `MIGRATIONS` list (index + 1 = schema version), a one-row
  `schema_version` table, applied by `Store.initialize()`. Version 1 creates `users`,
  `invite_codes`, `auth_sessions` and `characters` as the plan lists them. A database newer than the
  code is refused.
- `repository.py`: `Store` with user methods (create/get/get-by-name/delete) and character methods
  (create, get, list with name filter, update, delete, count). WP137 adds the invite and
  login-session methods on top. Their tables already exist.
- `tests/unit/test_store_wp136.py`: round trip, owner scoping, the quota boundary (100th succeeds,
  101st fails, overwrite at 100 succeeds), migration from an empty file, plus revisions, filtering,
  cascade delete and foreign keys.

## Decisions and traps

- **Quota check and insert share one `BEGIN IMMEDIATE` transaction**, so two concurrent inserts
  can't both pass the count.
- **`update_character(..., expected_revision=)` is already here** (raises `RevisionConflictError`),
  since the `revision` column is this WP's. WP138 only has to call it. Without the argument the
  write is unconditional and still bumps the revision. A wrong owner gives `None`, a stale revision
  gives the error, so callers can tell "gone" from "changed elsewhere".
- **Trap: `executescript` commits implicitly**, which would defeat a migration's transaction. The
  v1 schema is a list of single statements, and a test checks a failing migration rolls back.
- **Names are copied from the save on every write** (`names_from_save`: Biography `name` and
  `street_name`, top-level `metatype_name`). `display_name` here is the Bio *name*. The list page's
  "street name first, then name" fallback is WP139's presentation.
- **The filter is SQL `LIKE`**, so it is case-insensitive for ASCII only. `%`, `_` and `\` in the
  search text are escaped and match literally. Non-ASCII case folding is not handled; revisit if a
  player with accented names notices.
- Connections are opened per call (WAL and foreign keys set on each), with a 10 s busy timeout.
