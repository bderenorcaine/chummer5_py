# WP138 — The open character, autosave, and new-character flow

Chargen now edits a stored character. The first priority confirmation stores it, every
successful chargen POST autosaves it, and a lost session (a restart, an eviction, a new login) is
rebuilt from the user's last-opened character. Stale tabs and stale devices are refused instead of
overwriting.

## What landed

- **Store:**
  - Schema v3 adds `users.last_character_id`, which is set to NULL when that character is deleted.
  - New method: `set_last_character`.
- **`ChargenSession`:**
  - New fields: `character_id`, `revision`, `saved_digest` (a SHA-256 of the JSON last stored)
    and `last_used`.
  - Two locks: `lock` (an RLock) and `save_lock`.
  - Two methods: `snapshot()` and `adopt(other)`. `adopt` takes over everything about the
    character and keeps the browser's own preferences and locks.
- **`SessionStore`:**
  - Idle eviction (`sweep()`, run at most once every 60 s from lookups).
  - `get_or_create(key, factory)` runs the factory under the store lock.
  - `resolve_session` caches its result on `request.state`. The tab guard, the route and the
    autosave therefore all see one session, and a new cookie is set once.
- **`chummer5.web.persistence`** (new):
  - `restore_session`, installed as `app.state.session_restorer`.
  - `store_new` (quota-checked insert, then adopt).
  - `open_character`, `new_character`, `reload_session`.
  - `autosave`, which returns a `SaveOutcome` of SKIPPED, SAVED or CONFLICT.
  - `open_character_context`.
  - `store_middleware`: before the route, the tab guard. A mismatched GET gets `HX-Refresh`; a
    mismatched POST gets a 409 notice. After the route, the autosave, and on a conflict the 409
    "changed elsewhere" notice.
- **Routes:**
  - `POST /characters/new` and `POST /characters/{id}/open` (`routes/characters.py`).
  - `GET /ui/open-character`, the title-bar fragment.
  - `pages.shell_swap_response`.
  - `submit_priorities` stores on the first confirmation, and refuses it at quota.
  - Load and import store as new characters.
  - `character.build_from_save` is the one place a save meets the catalogs.
- **Templates:**
  - `base.html`'s body moved into `_app_shell.html`, whose `#app-shell` wrapper carries
    `hx-headers`.
  - The `htmx-config` `responseHandling` gets a 409 entry.
  - New: `_open_character.html` and `_stale_notice.html`.
  - The Export page's load and import forms get `hx-confirm`.
  - New static file: `tabs.js`.
- **Tests:** `tests/unit/test_open_character_wp138.py` (31 tests). The full suite: 1830.

## How the acceptance criteria are covered

| Criterion | Test |
|---|---|
| Edit visible after restart + re-login | `test_every_change_is_saved_and_survives_a_restart`, plus by hand: real uvicorn killed and restarted, re-login shows the Bio name |
| Quota confirmation refused, nothing stored | `test_confirmation_at_quota_is_refused_and_stores_nothing` (quota 2 stands in for 100; WP136 tests the 100 boundary itself) |
| Stale tab POST → 409, other character unchanged | `test_stale_tab_post_gets_the_notice_and_changes_nothing` |
| Back/forward after opening B sends B's id | `test_the_id_lives_inside_body_so_history_restores_renew_it` (a history-restore request renders B's id inside `<body>`, none on `<body>` itself) |
| Two clients, second autosave refused, first edit intact | `test_second_device_autosave_is_refused_and_the_first_edit_kept` |
| Prefs POSTs never autosave | `test_prefs_posts_never_autosave` |
| Switch warning only with a second tab; Cancel changes nothing | **Not run here (no Node or browser in the devcontainer).** Server side tested: the controls carry `hx-confirm` naming the character, and `tabs.js` is served and included. The prompt itself needs a check in a real browser. |

**Mutation check.** Each safeguard was broken in turn and its test failed: the revision check,
the tab guard, the save lock (5 out of 5 runs) and the unchanged-JSON skip.

## Traps hit

- **`hx-headers` goes stale inside a tab, not only across tabs.** After the first store, the
  confirming tab's wrapper still says `new`, so its next POST would be refused. The fix is the
  in-place shell swap for id-changing responses (decisions log).
- **Self-conflict.** Two autosaves of one session both send the revision they read. Fixed with the
  per-session `save_lock`.
- **The digest has to be of what this code writes.** On restore it is computed from a
  re-serialization, not from the stored bytes, so loading an older-format save doesn't cost one
  pointless write.
- **Import cycle:** `persistence` → `routes.character` → `routes.priorities`. The two routes that
  need `persistence` or `pages` import them inside the function, with a comment.
- **The bare-text guard caught operator messages in the web layer again.** The idle-timeout parser
  lives in `accounts.py`.
- The suite got about 10 s slower (38 → 48 s) because every local-mode chargen POST in the existing
  tests now autosaves to SQLite. That is accepted.
