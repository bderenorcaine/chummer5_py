# WP139 — The character list page

`GET /characters` lists the player's stored characters, newest change first, with a name filter,
a usage indicator, New, Open and Delete. A login or a registration now lands there. The chargen
title bar links to it.

## What landed

- **Routes** (`web/routes/characters.py`, which already held WP138's open/new):
  - `GET /characters`: the whole page, or with `HX-Request` (and not a history restore) only the
    list fragment, for the filter box. `Vary: HX-Request`, like the step pages.
  - `POST /characters/{id}/delete`: owner-scoped (someone else's id is a 404, like open). It
    answers with the list fragment, keeping the filter (`hx-include="#character-filter"`).
    Deleting the open character ends in `persistence.new_character()`.
- **Paths:** `auth.CHARACTERS_PATH`, shared by the route, the tab guard's unguarded paths and
  `account.py`. `account.LANDING_PATH` (the list) is where login, registration and an
  already-logged-in visit to `/login` or `/register` go. A password change still goes to `/`,
  since the player carries on with the open character.
- **Templates:**
  - `characters.html` (the page) and `_character_list.html` (the swapped part: toolbar, quota
    reason, table or empty state).
  - The title bar's prefs and account blocks moved out of `_app_shell.html` into
    `_titlebar_prefs.html` and `_titlebar_account.html`, so the list page has the same pickers
    and links. Their context comes from `pages.prefs_context(session)`, which `_shell_context`
    now uses too.
  - `_open_character.html` gets the "My characters" link.
- **`tabs.js`:** two attributes (see below).
- **CSS:** `.list-shell*` and `.character-list*`. The `.page` table rules now also apply under
  `.character-list`, so every theme's table tokens style the list.
- **Strings:** 15 new `Web_Characters_*` keys. The column heads, Delete and Open reuse legacy
  `String_Name`, `String_Metatype`, `String_Delete` and `Label_Open` (exact English matches, so
  they come translated).
- **Tests:** `tests/unit/test_character_list_wp139.py` (24 tests, including one per theme). Four
  WP137 assertions changed from `/` to `/characters` (the landing). Full suite: 1854.

## Decisions

- **The list is a page of its own, not a step inside the chargen shell.** The step nav, resource
  panel and validation status all describe the open character, and the list isn't about it.
  Being outside `#app-shell` also means its requests carry no `X-Character-Id`, so nothing on it
  is tab-guarded.
- **Delete always confirms; Open and New only with another tab open.** WP138's `tabs.js` drops
  the confirmation when no other tab answers, which suits a switch but not an irreversible
  delete. A control with `data-confirm="always"` now always asks. Its `data-confirm-tabs` text (set
  only on the open character's Delete) is added when another tab is open. That is the spec's
  "carries WP138's other-tabs warning".
- **The list tab doesn't count as another tab.** `<body data-tabs-passive>` makes `tabs.js` ask
  but not answer pings. Switching characters elsewhere doesn't break the list, so a list tab left
  open shouldn't make every switch in the chargen tab ask. The attribute is read at message time,
  since `tabs.js` runs in `<head>` before `<body>` exists.
- **No confirmation when nothing would switch.** New skips `hx-confirm` while no character is
  stored (nothing can be entered before the priority confirmation). The open character's row
  shows "Continue" (a plain link to `/`) instead of Open.
- **Usage counts all characters, not the filtered matches.** At quota, New is `disabled` with the
  existing `Web_Characters_QuotaReached` text as its visible reason (`aria-describedby`). The
  server doesn't need its own refusal for New, since New stores nothing. The priority
  confirmation already refuses at quota (WP138).
- **Times are shown as UTC to the minute**, labelled "UTC", inside `<time datetime=…>`. Converting
  to the viewer's zone would need either a script or guessing the zone server-side. Neither is
  worth it for one group of players.
- **Download and Upload are left to WP140.** The phase lists download among the list's actions,
  but both routes are WP140's deliverables. Its entry now says where they go on the list page.

## Traps hit

- `document.body` is null when `tabs.js` runs (it is in `<head>`), so the passive check had to
  move into the message handler.
- A test asserting a name was *not* in the filtered list failed because that character was the
  open one, and its name is in every switch question ("Leave “Bob”?"). Worth knowing for any later
  test that greps the list for an absent name.

## Not checked here

As in WP138, there is no browser in the devcontainer. The `tabs.js` changes (always-confirm, the
added tabs sentence, the passive list tab) are covered only by the server-side attributes the
tests check. They need a check in a real browser.
