# WP140 — Download and upload

Each stored character can be downloaded as its JSON save. Any number of JSON saves or legacy
`.chum5` files (up to 20) can be uploaded, and each becomes a new character, quota-checked per
file. The Export page's two forms (load, import) became one upload form on the same route.

## What landed

- **`chummer5.web.uploads`** (new):
  - `read_upload`: a subclass of Starlette's `MultiPartParser` that keeps at most the cap of each
    file and then drops the rest of that file's bytes. Such a file comes back with `data=None`, so
    the other files in the request still get their own results.
  - It refuses a 21st file, and caps the whole body (checked against `Content-Length` before
    reading, then counted while reading).
  - `import_file`: detects the format by content and returns the save and notes, or a translated
    error.
- **Routes** (`web/routes/characters.py`):
  - `GET /characters/{id}/download`: the stored JSON verbatim, owner-scoped. The filename is the
    shown name with runs of anything outside `[A-Za-z0-9_-]` turned into `_`, falling back to
    `character`.
  - `POST /characters/upload`: the import and store run in the thread pool. From the list, it
    answers with the list fragment plus per-file result lines. With `?open=true` (the Export
    page), it opens the last stored character and answers with the whole shell, or with the sheet
    and the error.
  - `POST /character/load` and `POST /character/import-chum5` are removed. `character.py` keeps
    `sheet_fragment`/`switched_response` (now public) for the Export page's answers.
- **`persistence`:** `store_new` is split into `insert_new` (store and stamp) and `adopt_stored`
  (open), so a list upload can store without opening.
- **`io`:** `load_chum5`/`import_chum5` take a `Path`, bytes or a binary file, which retires the
  temp-file workaround. They always parse through `defusedxml` (new runtime dependency;
  `types-defusedxml` in dev).
- **Config:** `CHUMMER5_UPLOAD_MAX_MB` (default 10; `store/config.py`).
- **Templates:**
  - The list's toolbar gets an Upload form (multiple files, disabled at quota) and a results list.
  - Each row gets a Download link.
  - The Export page gets one upload form, and its download link points at the stored copy.
- **Strings:** 11 `Web_Upload_*` keys added. The 8 load/import keys they replace were removed. The
  row's link reuses legacy `Button_Download`.
- **`deploy/Caddyfile.example`:** `request_body max_size 210MB` (see decisions log).
- **Tests:** `tests/unit/test_upload_download_wp140.py` (31 tests). About 30 existing tests moved
  from the two removed routes. Full suite: 1884.

## Acceptance

| Criterion | Test |
|---|---|
| Download → upload round trip gives an equal save | `test_download_and_upload_round_trip_to_an_equal_save` |
| Every `.chum5` fixture imports through the route | `test_every_chum5_fixture_imports_through_the_upload_route`: all 34 legacy test files, not just the registered ones, in batches of 20. Each gives the same outcome as a direct import. |
| A file declaring an entity is refused with a translated error, not a 500 | `test_entity_declarations_are_refused_with_a_message` (an entity bomb and an external entity), plus the Export-page variant |
| An oversized file is refused without being fully read | `test_the_parser_keeps_no_more_than_the_cap` (the spooled copy stops at the cap), `test_an_oversized_file_is_refused_and_the_rest_still_import`, `test_a_declared_body_over_the_limit_is_refused_before_reading` |
| At 99, three files import one and report two quota errors | `test_at_99_three_files_import_one_and_report_two_quota_errors` |

## Decisions

The full reasoning is in the decisions log. In short:

- 10 MB per file, not 5.
- A list upload opens nothing, so it has no switch warning.
- One route and one form; the old routes are removed.
- `defusedxml` for every `.chum5`.

Smaller ones:

- **"Too large" means "past the cap, nothing more is kept".** The rest of that file's bytes are
  still read off the connection and dropped. That lets the other files in the same request
  through, and lets the response be delivered cleanly. A body that keeps going past the
  whole-request cap is cut off instead.
- **Detection:** a file whose first non-whitespace byte (after a BOM) is `<` is a `.chum5`.
  Anything else is JSON, unless it is *named* `.chum5`/`.xml`. Then it is reported as a bad
  `.chum5`, the error its owner expects (this keeps the old "Not a valid .chum5 file" test true).
- **Well-formed XML the importer still can't take** (`ValueError`, `KeyError`, …) is reported as
  "Cannot import: …". Before, it was a 500.
- **The open flag is a query parameter (`?open=true`), not a form field.** That way it is known
  even when the body is refused before parsing.

## Traps hit

- **A real legacy save is 5.7 MB** (embedded mugshots). The spec's 5 MB default would have refused
  it. The fixture-corpus test caught it.
- **Two legacy files crash the importer** with a plain `ValueError` (adept powers at rating 0).
  This was hidden until now because the old route's tests used only registered fixtures. It is
  logged as a finding; the importer is not changed here.
- **Line-number `sed` after `ruff format` hit the wrong line.** Repaired with `git checkout` on
  that test file, which also discarded the file's route migration. That had to be redone. Use
  content matches, not line numbers, once a formatter has run.
- The bare-text guard flags multi-word exception texts and f-string headers in web-layer Python.
  The internal exception texts became single tokens, and the `Content-Disposition` template joined
  the guard's allowlist.

## Not checked here

No browser in the devcontainer. The upload forms' htmx behavior (multipart encoding, the results
swap, and Upload's `disabled` state at quota) is checked only through the rendered markup and
the route responses.
