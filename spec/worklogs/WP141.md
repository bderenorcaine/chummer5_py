# WP141 — Security pass

The protections an internet-facing deployment needs, in one place (`chummer5.web.security`) and
listed in `spec/security.md`, which future WPs keep true.

## What landed

- **`chummer5.web.security`** (new):
  - `security_headers` (CSP, nosniff, Referrer-Policy, X-Frame-Options; every response, both
    modes).
  - `check_origin` (hosted: non-GET requests must come from `CHUMMER5_PUBLIC_URL`'s origin).
  - `limit_body` (1 MB except the upload; chunked bodies get 411).
  - `install_error_pages` (hosted: generic pages for HTTP errors, validation errors and 500s).
  - `Throttle` and `client_ip`.
- **Middleware order** (outermost first): headers, body cap, origin check, login gate, tab
  guard/autosave, `chargen-changed`.
- **Config** (`accounts.py`): `public_origin()` (required in hosted mode, read at startup),
  `trusted_proxies()` and `origin_of()`.
- **Throttle** in `routes/account.py`: `_throttled(request, keys, attempt)` wraps login,
  registration and password change, with keys per account and per address.
  `ThrottledError` gives 429.
- **Cookies:** `session.set_session_cookie` replaces 26 copies of the `set_cookie` line. The auth
  cookie is `Secure` always.
- **CSP clean-up:**
  - `static/app.js` holds `base.html`'s details store and the Skills, gear and Spells filters
    (formerly inline in their fragments).
  - The `number-input` event replaces htmx event filters in 11 templates.
  - `htmx-config` hardening in `base.html` and `characters.html`.
- **`catalogs._root_relative_url_for`:** templates' `url_for` gives paths.
- **Bounds:** `biography.max_length` (2000 for one-line fields, 20000 for long ones), plus
  `maxlength` on the Bio inputs.
- **`templates/error.html`** and 7 `Web_Error_*` / `Web_Auth_Throttled` strings.
- **`deploy/test-image.sh`:** the hosted container gets a public URL. New checks: CSP present,
  root-relative assets, cross-origin 403. Registration takes the token off `Set-Cookie` (curl
  neither keeps nor sends a `Secure` cookie over http). Those exact check commands were run here
  against a live hosted uvicorn and passed. The image itself still needs the user's host.
- **`spec/security.md`**, plus `admin-primer.md` notes (throttle message, `CHUMMER5_PUBLIC_URL`,
  "every form refused" in the site-down list).
- **Tests:** `tests/unit/test_security_wp141.py` (50 tests). `tests/fixtures/hosted.py` provides
  the hosted client (https base URL plus `Origin`). Three older tests that pinned inline-script
  text now check `app.js`. Full suite: 1934.

## Acceptance

| Criterion | Test |
|---|---|
| A cross-origin POST is refused | `test_a_cross_origin_post_is_refused`, `test_login_itself_is_origin_checked`, `test_missing_or_foreign_origins_are_refused` (five variants) |
| The 6th bad password in a row is throttled | `test_the_sixth_bad_password_in_a_row_is_throttled` (the correct password is refused too while throttled) |
| Every theme renders under the CSP with no console violations | `test_every_page_under_every_theme_is_csp_clean` covers every enabled step page, the list and the sheet, under all four themes. `test_no_template_carries_code_the_csp_would_block` covers every template branch. **A browser console check was not possible here** (no browser in the devcontainer): the tests check what would violate the policy (inline scripts and styles, handlers, eval-needing htmx, off-site URLs, missing htmx-config hardening), not the console itself. |
| A forced 500 shows a generic page | `test_a_forced_500_shows_a_generic_page` (no exception text, no traceback, headers present) |

## Traps hit

- **htmx event filters are `eval`.** `hx-trigger="input[event.target.type=='number']"` looks like
  markup but is compiled with `new Function`. Under `script-src 'self'` every number input on
  every step would silently have stopped autosubmitting. The plan only warned about `base.html`.
- **Swapped-in inline scripts.** Three fragments carried `<script>` blocks that htmx re-ran on
  each swap. The filters had to become `document`-level listeners, and the skill filter's state
  restore moved to `htmx:load`.
- **`url_for` absolute URLs** would have broken the CSP and caused mixed content behind Caddy,
  depending on uvicorn's proxy-header trust and rootless podman's peer address. Root-relative
  paths sidestep both.
- **`Secure` cookies and test clients.** httpx won't send them over `http://testserver`, and curl
  won't even keep them over http. Hosted tests moved to `https://testserver`, and
  `test-image.sh` reads the token off the header.
- **The bare-text guard** flags CSP strings with spaces in web-layer Python, so the policy is
  built from single-token pairs.
- Killing the scratch uvicorn with `pkill -f` matched the invoking shell (exit 144). Find PIDs
  with `ps` and kill those.

## Left open

- `CHUMMER5_TRUSTED_PROXY` must match the address Caddy's connections arrive from inside the
  container. Under rootless podman that has to be checked on the server (WP142's note).
- The throttle is per process and resets on restart. That is fine with one worker.
