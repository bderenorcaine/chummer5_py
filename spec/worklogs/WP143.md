# WP143 — Priorities redesign: server side, markup and layout

First Phase Z WP. The Priorities page now has the sketch's layout
(`examples/ui/priorities.png`), in both methods, with the live summary and status computed on the
server. Drag and spinner interaction is WP144's; until it lands, Priority tiles don't move and
Sum-to-Ten values don't change in a browser.

## What landed

- **`engine/build_method.nearest_priority_assignment`**: five letters in display order (Heritage,
  Talent, Attributes, Skills, Resources) → the nearest Priority assignment. It sorts the
  categories stably by letter and hands out A–E in that order. Tests: all E, five distinct letters
  unchanged, five mixed cases, malformed input, and a brute force over all 3125 inputs against
  all 120 permutations.
- **`web/routes/priorities.py`**:
  - `PrioritySelection` (method, five letters, metatype) is the one shape for both the session's
    confirmed selection and the form's current one. Equality between the two *is* the status.
  - `_priority_form_context(selection, session, error)` replaces the old keyword-per-letter
    signature. Every key is `priority_`-prefixed, because `chargen_context` merges every step's
    context over it. The first draft used `priority_summary`, which the Export sheet already
    uses for something else. The tests caught it, and it is now `priority_gives`.
  - New read-only GETs: `/ui/priorities/preview` (status, buttons, summary, and the Metatype
    field out of band when the offer changed), `/ui/priorities/layout` (method switch) and
    `/ui/priorities/revert`. All three refuse letters outside A–E (422). Layout also refuses an
    unknown method. Only hand-crafted requests can send either.
  - `POST /ui/priorities` is unchanged in contract (Finding 1). `metatype_id` is now
    `Form("")`, so the placeholder's empty value gets the itemized "select a metatype" error,
    not a 422. Its final render goes through the same `_render_panel` as layout and revert.
  - `GET /ui/metatypes` and `_metatype_select.html` are gone. They served the Heritage dropdown,
    which no longer exists. The preview's out-of-band Metatype field replaces them.
- **Templates:** `_priority_form.html` (rewritten), `_priority_preview.html` and
  `_priority_metatype.html` (new).
- **`app.css`:** a "Priorities page" section, theme tokens only.
- **i18n:** new `Web_Priorities_*` keys for the intros (one per method), status texts, Revert,
  "Choose metatype", the spinner texts and buttons, the ∑ title, and the summary's `Gives*`
  family (with `_One`/`_Other` where a count is shown). `Web_Priorities_Confirm` is now just
  "Confirm", as in the sketch. Removed: `Web_Priorities_Intro`, `MethodPriority`,
  `MethodSumToTen`, `SumToTenTotal` (its meaning changed, so the new key has a new name:
  `SumToTenTotalLabel`), `SummaryBuildMethod` and `SummarySpecialPoints`. The other five
  `Summary*` keys stay: the Export sheet uses them.
- **Tests:** `tests/unit/test_web_priorities_redesign_wp143.py` (40 tests, including both layouts
  × four themes CSP-clean). Five existing tests were updated for the new markup, and the
  `/ui/metatypes` test was dropped with its route. Full suite: 2009.

## Decisions and traps

- **The method dropdown sits outside the `<form>`, joined with `form="priority-form"`.** The
  preview listens for `change from:#priority-form` (the Metatype select) and a custom
  `priority-input` event (WP144's script). If the method select were inside the form, its
  `change` would bubble there too and fire a preview racing the layout swap. htmx 2 builds form
  values from `form.elements`, which includes form-associated controls outside the element, so
  POST and `hx-include="#priority-form"` still carry `build_method`.
- **The preview region is a stable container, swapped `innerHTML`.** The form's `hx-target`/
  `hx-swap` are inherited by everything inside it, so the container has to override both
  explicitly (`hx-target="this"`, `hx-swap="innerHTML"`). `hx-sync="this:replace"` aborts a
  preview still in flight when a newer one starts, so an old response can't overwrite a newer
  one.
- **"Has the metatype offer changed?"** compares the *choices* for the submitted Heritage letter
  with those for the letter the field was rendered for (`metatype_offer`, a hidden input inside
  the field, so it is replaced along with it). A and B offer the same metatypes but different
  special attribute points, which the option labels show. So A → B does re-render the field,
  keeping the selected metatype.
- **A never-confirmed page shows "Choose metatype", not Human.** Before, the first option was
  implicitly selected. The phase file's rule ("never silently pick a metatype") and the
  no-default-distribution ruling both point this way, so it's added to the phase file's
  "Defaults". The page therefore opens unconfirmable until a metatype is chosen.
- **The Priority layout always renders a permutation.** A duplicate-letter POST (hand-crafted,
  since the UI can't produce one) is echoed through `nearest_priority_assignment`, so every
  tile's hidden input matches its row. The error still shows, and the server-side duplicate
  check stays.
- **Conversion: optimal, but not the only optimum.** Sorted matching minimises the total letter
  distance. But other permutations can tie with it when the player's ranking is inverted. For
  example, H=C, T=B, Attributes=A, Skills=A, Resources=E gives Heritage D and Talent C, and
  Heritage C with Talent D costs the same. The stable sort is the one optimum that never ranks a
  category below one the player put lower. So "ties broken by display order" applies to equal
  *letters*, which is what the brute-force test checks (minimal, plus order-preserving with
  display order on equal letters). Recorded in the function's docstring.
- **Messages:** the POST error is the last thing in the preview region, so it disappears on the
  first edit. It described a submission the form no longer holds. The stale-selections warning
  is the session's state, so it sits after the region and needs no `chargen_context` on every
  preview.
- **Column width:** `max-width: 30rem`, centred. Below that it takes the pane's width inside the
  pane's own padding (1.25rem). I didn't add another 1rem inside that.
