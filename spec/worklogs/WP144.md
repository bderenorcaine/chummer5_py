# WP144 — Priorities redesign: drag-to-reorder and Sum-to-Ten spinners

The client-side widgets on top of WP143's markup. After this, the redesigned Priorities page can
be used in a browser. Nothing here decides a rule. The script moves tiles and steps spinners,
writes the hidden `<category>_letter` inputs, and asks the server for a preview. The server still
decides the status and whether the form is confirmable.

## What landed

- **SortableJS 1.15.7, vendored** in `static/vendor/sortablejs/`: `Sortable.min.js`, its MIT
  `LICENSE` and `VENDORED.md`. The version, source and checksums are recorded there:
  - The npm tarball's SHA-1 matched the registry's `dist.shasum`.
  - The file's SHA-256 matched the copy unpkg serves.

  `NOTICE` lists it. `base.html` loads it after htmx and before `app.js`. The library has no
  `eval` or `new Function`. Its one style write is a CSSOM `cssText` feature probe, which
  `style-src 'self'` doesn't govern.
- **`static/app.js`**, a new WP144 section (same IIFE, document-level listeners):
  - **Drag:** one `Sortable` per `#priority-tiles`, created on `htmx:load`. Every swap that
    brings the panel back (navigation, method switch, Revert, CONFIRM, the first-confirm shell
    swap, a history restore) gets one. `Sortable.get` stops a second instance on the same list.
    A list being cleaned up by htmx has its instance destroyed. Touch drags wait 250 ms
    (`delayOnTouchOnly`), so a swipe over the tiles still scrolls the page. `onUpdate` rewrites
    every tile's input to its row's letter (from `data-priority-letters`), announces the moved
    tile, and dispatches `priority-input` on the form.
  - **Keyboard:** Alt+↑ / Alt+↓ on a focused tile. The script moves the *neighbour* past the
    tile rather than the tile itself, because moving a focused node drops its focus in most
    browsers. It then calls `focus()` anyway, and runs the same rewrite, announce and preview
    routine.
  - **Announcements:** `#priority-live` (`aria-live="polite"`, visually hidden) gets the moved
    tile's `data-announce-<letter>` text. The server renders that text for each letter
    (`Web_Priorities_MovedTo`), so the script composes no prose. A visible hint
    (`Web_Priorities_ReorderHint`, linked from the list by `aria-describedby`) tells keyboard
    users the shortcut.
  - **Spinners:** ▲/▼ and ↑/↓ step along the hidden scale the server rendered. Up moves towards
    A. The value clamps at E and A, with no wrapping. Each step updates `aria-valuenow`,
    `aria-valuetext`, the visible text (copied from the scale item), the hidden input, the ∑
    `<output>` and its off-target highlight, then asks for a preview. Clicking a step button
    focuses the value, so the wheel and arrow keys act on it next.
  - **Wheel:** handled only when the event is over a `.sum-to-ten__spinner` *and* that row's value
    has focus. Only then does it call `preventDefault`, on a `{ passive: false }` listener. A
    line- or page-mode event, or a pixel delta of 50 or more (a mouse notch), is exactly one
    step. Smaller pixel deltas (trackpads) accumulate and step once per 50. The sum resets when
    the direction reverses, when another spinner is used, or after 250 ms of quiet.
  - **CONFIRM:** the script only ever *disables* it, while ∑ is off target. After every preview
    swap it applies that again: a preview answered for an older, on-target state must not
    re-enable CONFIRM for the newer, off-target one.
- **Markup** (`_priority_form.html`): the tiles' `data-announce-*`, the hint, and the live
  region. **CSS:** Sortable's ghost and chosen states, the hint, `.visually-hidden`.
- **Tests:** 5 more in `test_web_priorities_redesign_wp143.py`:
  - the vendored file, its license, its checksum on record, and `NOTICE`;
  - the file is served, and included between htmx and `app.js`;
  - the hooks in each layout;
  - every class and id the WP144 script selects on is in the rendered markup, so renaming one
    side fails in pytest rather than silently in a browser.

  `app.js` was syntax-checked with a throwaway `esprima` (`uv run --no-project --with esprima`).
  It is not a project dependency. Full suite: 2014.

## Traps considered

- **The preview arrives late.** `hx-sync="this:replace"` on `#priority-preview` (WP143) aborts an
  in-flight preview when the next one fires. The ∑ re-guard after each swap covers the window
  before that.
- **htmx attribute inheritance.** Revert sits inside `#priority-preview`, so it inherits
  `hx-sync`. Its `this` resolves to the preview container, so a Revert click aborts a pending
  preview instead of racing it. That's the behaviour we want.
- **Focus during previews.** The preview swaps only `#priority-preview`'s contents, never the
  tiles or spinners, so a focused tile or spinner keeps focus while the summary updates.

## Manual browser checklist — not run here

There is no browser in the devcontainer. For the user to work through:

1. **Mouse drag:** drag a tile to another row. The others shift by one, the summary updates
   (≈150 ms later), and the status reads "Changed — not confirmed yet" (after a first confirm).
2. **Touch, phone in portrait:** a swipe starting on a tile scrolls the page. A press-and-hold
   (~¼ s) picks the tile up and drags it. The column fills the width with no horizontal scroll.
3. **Keyboard:** Tab to a tile, then Alt+↑ / Alt+↓. It moves one row and keeps focus. A screen
   reader announces e.g. "Heritage: priority B". At the top or bottom row nothing happens.
4. **Spinners:** ▲/▼ buttons and ↑/↓ on a focused value. Up goes towards A, and the value stops
   at A and at E. The visible "B (3)" text and the ∑ total update immediately.
5. **Wheel on a focused spinner:** with the pointer over it, one notch is one step and the page
   doesn't scroll.
6. **Wheel ignored:** over an *unfocused* spinner, or over a focused spinner's row label, the page
   scrolls and no value changes.
7. **Trackpad:** a two-finger swipe on a focused spinner steps a few times, not dozens.
8. **∑ and CONFIRM:** off target, ∑ is highlighted and CONFIRM is disabled at once. Back on
   target with a metatype chosen, CONFIRM enables after the preview returns. Step quickly
   through an on-target value to an off-target one: CONFIRM must not stay enabled.
9. **Preview:** the summary's "old → new" lines follow every drag, step and metatype change.
   Changing Heritage so the metatype isn't offered resets the field to "Choose metatype".
10. **Re-initialisation:** after a method switch (both ways), Revert, a CONFIRM and the very first
    CONFIRM (the shell swap), dragging, keys and spinners all still work, and a drag moves the
    tile only once (no double instance).
11. **Themes:** classic, Shadowrun, Shadowrun 4 and sketch, in light and dark. Tiles, the drag
    ghost, the dot leaders, the ∑ highlight and the status colours are all legible.
