# WP146 — Attributes redesign: budget boxes, autosave only

Second Phase Z redesign (`examples/ui/attributes.png`). The budget sentence became three boxes and
the dead Update button went. No client script changed: the existing `number-input` hook in
`app.js` still drives autosave.

## What landed

- **`_attribute_allocation.html`**: no `<details>` wrapper; a plain `<h1 class="page__heading">`;
  three boxes (Primary, Special, Karma with the "(5 x level)" hint) in one row; the same table;
  no submit button; error and stale-budget warning moved below the table. `#attribute-allocation`
  is still the swap target. The box value is `remaining/budget`, and a box gets
  `attribute-budget--over` when remaining < 0, decided in the template from the context values
  the route already computed. `routes/attributes.py` is untouched.
- **i18n**: legacy keys reused for the labels (`Label_SummaryPrimaryAttributes`,
  `String_SpecialAttributes`, `String_Karma`, `Label_Attributes`), one new key
  `Web_Attributes_KarmaCostHint`. The four "…Remaining" sentences and `Web_Attributes_Update` were
  removed; nothing else used them. The Edge vs Edge/Magic wording distinction is gone (one
  "Special Attributes" label, per the phase file's default).
- **CSS**: "Attributes page (WP146)" section at the end of `app.css`. Column cap 40rem; boxes are a
  three-column grid that never wraps; the over modifier reuses `--error-fg`/`--error-bg`, the
  Sum-to-Ten off-target colours; the table sits in an `overflow-x: auto` wrapper so a phone scrolls
  the table, never the page.
- **Focus trap**: the inputs had no `id`, so htmx's focus restore after the `outerHTML` swap had
  nothing to match. They now carry `attr-<CODE>` / `karma-attr-<CODE>`. Covered by a test, but the
  actual keep-focus behaviour needs a browser (checklist below).
- **Tests**: the five old assertions on the sentence wording now match the box values
  (`20/20`); new tests for three boxes / no button / no details, the over highlight (the WP19
  lowered-letter scenario: -1/14 flags only the primary box), stable ids, and document order of
  the table and the error. Full suite green.

## Traps hit

- My first `_budget_boxes` regex matched the `attribute-budgets` container as if it were the first
  box. The pattern now requires exactly `attribute-budget` plus the optional over modifier.
- Over-budget *posts* are rejected with state unchanged, so an overspent box can't be reached by
  posting. The only way in is lowering the Attributes letter after spending (WP19).
- A blanket replace of `f"{budget} / {budget}"` also hit a Skills assertion with the same text;
  reverted.
