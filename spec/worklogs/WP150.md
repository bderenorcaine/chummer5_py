# WP150 — Skills redesign: Filtered and Rated tabs, portrait dropdown

Last of the three Skills WPs: the two view tabs that replace the old filter box and the "rated
only" checkbox, and the dropdown that replaces the strip at narrow widths.

## What landed

- **Two more view tabs** in `SKILLS_TABS`, after Special: `filtered` and `rated`. On either one,
  both fragments render every panel that has rows, except Group. That covers the five categories,
  Magical, Special, and the Knowledge table. Each panel sits under an
  `<h2 class="skills-panel__heading">` (the tab's label) and is marked `data-skills-view`.
  Resonance has no rows, so it stays hidden. `CATEGORY_TABS` now carries each tab's label key for
  the headings.
- **Rows carry what the script narrows by:** `data-skill-key` (the row's `dom_id`, or
  `knowledge-<i>`), `data-skill-name` (the translated name in lower case, plus an exotic
  instance's item), and `data-skill-rating` (a native language counts as rated).
- **The filter field** (`#skill-filter`, `type="search"`, no `name`) sits at the top of the
  active-skills fragment, outside its form, so typing never autosaves. It appears on the Filtered
  tab only.
- **Both forms keep the view across autosaves.** The skills route accepts `filtered`/`rated` as
  `skills_tab`. The knowledge form now posts the tab it is on, and its route re-renders
  `knowledge` / `filtered` / `rated` (`KNOWLEDGE_VIEW_TABS`); anything else counts as Knowledge.
  Each fragment wrapper carries `data-skills-tab` for the script.
- **`app.js`**: the old `skillFilter` / `applySkillFilter` / `restoreSkillFilter`, which were
  no-ops since WP148, now drive the views. `narrowSkillViews(keep)` hides each
  `[data-skills-view]` row that doesn't pass, and hides a section with no row left.
  - *Filtered:* the query is stored. A freshly rendered field gets it back once, and every
    `htmx:load` reapplies it, because a Knowledge autosave brings new rows but not a new field.
  - *Rated:* the keys of the rows rated when the tab is *entered* are stored, and every later load
    reapplies them, so a row set to 0 stays until the player leaves the tab. "Entered" means the
    loaded element is (or contains) `.page--skills`: a tab click, history, or a reload. A fragment's
    own autosave swap and the strip's refresh are not entries. Leaving the tab clears the set.
- **Narrow widths:** `_skills_tabs.html` also renders `.skills-tabs__narrow`, which holds all four
  counters as one row of equal cells and a `<select id="skills-tab-select">` of every tab in
  strip order. The current tab is `selected`, Resonance is `disabled`, and a stale tab's label gets
  a ⚠. The script turns a change into `.click()` on the strip's own hidden link for that tab, so
  htmx makes the same request and pushes the same history entry as a tab click. No URL is built
  in the script, and nothing inline.
- **The breakpoint is a container query**, not a media query. `.page--skills` is
  `container-type: inline-size`, and `@container (max-width: 41rem)` swaps strip for dropdown. The
  column's width depends on the sidebar, which takes part of a wide window and stacks above the
  content below 40rem, so the viewport width doesn't say whether the strip fits. 41rem is the
  strip's own width: twelve 2.2rem tabs minus their 1px overlaps, plus the 5rem lean and the 9rem
  minimum filler.
- **i18n:** `Web_Skills_TabFiltered`, `Web_Skills_TabRated`, `Web_Skills_FilterLabel`,
  `Web_Skills_FilterPlaceholder` ("Part of a skill's name"). The dropdown's `aria-label` reuses
  `Web_Tabs_AriaLabel`.

## Follow-up: messages at the bottom, ratings-only views (user rulings, 2026-10-25)

The first cut had two limits. The user ruled both away:

- **Messages at the bottom of the page.** On Filtered/Rated, an active-skills error used to sit
  between the Special and Knowledge sections, because each form's messages lived inside its own
  swap target. Now both message regions (`_skill_messages.html` `#skill-messages`,
  `_knowledge_messages.html` `#knowledge-messages`) live in a footer, `_skills_footer.html`, which
  `_page.html` includes after the fragments through the new `StepPage.tab_footer`. Each POST
  appends its own region with `hx-swap-oob="true"` (`oob_messages` in the context), the pattern the
  step nav and the Priorities preview already use. So messages are at the bottom on every tab,
  including the Knowledge tab, where the active-skills ones used to be hidden. One carry-over: a
  Knowledge POST doesn't refresh the active-skills warning, even though Knowledge spending Active
  points can change it. That was already true before; the next page render shows it.
- **Filtered and Rated only change ratings.** No Add Special Skills or Add Knowledge Skill
  buttons, no exotic add row, no blank or nameless Knowledge rows. A Knowledge row's name,
  category and Native are text there, posted back through hidden fields, so an autosave from the
  view keeps the row as it was. Kn/Ka points and specializations stay editable. This also removed
  the first cut's "a row added on Rated stays hidden" limitation.

Tests: `test_web_skills_views_wp150.py` gained the footer on four tabs (a stale warning after
every section and outside both fragments), each POST's out-of-band region (and only its own),
and both views being ratings-only, including a round trip of the hidden Knowledge fields. The
WP148/WP149 message-order tests now look for the out-of-band region. Full suite green (2094).

## Known limit

- After an autosave on a view, the swapped-in fragment shows every row until `htmx:load` narrows
  it again. That should be invisible (htmx fires it before the next paint), but it is on the
  checklist.

## Manual browser checklist — not run here

- [ ] Filtered: typing narrows rows across the active categories, Special and Knowledge; a section
      with no match disappears; clearing the query brings everything back.
- [ ] The query survives an autosave (change a rating on Filtered; the field keeps its text and
      the rows stay narrowed), including a Knowledge autosave.
- [ ] Rated: shows only rated rows; setting one to 0 keeps it listed; leaving the tab and coming
      back drops it.
- [ ] An error (e.g. overspending skill points) shows at the bottom of the page on every tab,
      including Filtered/Rated, below the Knowledge section; fixing it clears it.
- [ ] Filtered/Rated: no Add buttons; Knowledge names and categories are plain text.
- [ ] No visible flash of unfiltered rows after an autosave on either view.
- [ ] Narrow column (portrait phone, or a desktop window narrow enough): the strip is replaced by
      the dropdown, the four counters sit in one row above it, and the page never scrolls sideways.
      Choosing a tab navigates, and the back button returns to the previous tab.
- [ ] Widening the window back past the breakpoint restores the strip.
- [ ] The four themes, light and dark: the filter field, the section headings, the counter row and
      the dropdown.
