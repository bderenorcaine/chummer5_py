# WP151 — Spells redesign: strip, counters, category tabs

Fifth Phase Z redesign ("Redesign 5", no sketch), first of two WPs. The Magic page's Spells sub-tab
now looks like the Skills page: an angled strip with one tab per spell category, three counters, and
one panel per category. Filtered, Known and the portrait dropdown are WP152.

## The shared strip

The phase file asked for the Skills strip's pieces to become shared ones in this commit:

- **`_view_tabs.html`** is a macro, `view_tabs(id, aria_label, items, current, counters_start,
  counters_end, refresh_url, select_id)`, imported `with context` because the labels and reasons go
  through `_()`. Each item is a dict (`slug`, `href`, `stale`, `enabled`, `disabled_reason_key`),
  and the item whose slug equals `current` is the marked tab.
- **Labels come from a caller block** (`{% call(item) view_tabs(...) %}…{% endcall %}`). Skills
  labels are i18n keys (`_(item.tab.label_key)`), but spell categories are data terms
  (`item.category | dterm("spells.xml")`). Neither the macro nor the context builders can render
  the other kind: context builders have no locale. The caller block renders the label in both the
  strip and the dropdown option.
- **`current` is a macro argument, not an item flag.** The Spells context is built inside
  `chargen_context` before the URL's view is known, and the shell sets `spells_tab` afterwards. If
  each item carried its own `current` flag, the items would have to be built again.
- **`refresh_url` is optional.** Skills keeps its `chargen-changed` re-fetch, because two forms
  change its counters. The Spells strip sits inside the Spells fragment, so each autosave
  re-renders it, as the phase file's default says.
- **`select_id` is optional.** Without it, no narrow block is rendered. Spells passes none until
  WP152.
- **Classes and partials renamed:**
  - `.skills-tabs*` → `.view-tabs*`
  - `.skills-tab*` → `.view-tab*`
  - `.skills-counter(s)*` → `.view-counter(s)*`
  - `_skills_counter.html` → `_view_counter.html` (a `git mv`)
- **CSS:** the strip CSS moved out of the Skills section into its own "View-tab strip (WP148,
  shared since WP151)" section. The WP150 breakpoint is now scoped to `.page--skills`
  (`@container (max-width: 41rem) { .page--skills .view-tabs__strip … }`), because Spells will need
  its own breakpoint.
- **Ids are unchanged:** `skills-tabs` and `skills-tab-select`, and so are the `data-skills-*`
  attributes. Making the view script page-agnostic is WP152.
- **Skills unchanged, verified:** I rendered the Skills strip (Vehicle tab) from a `git worktree`
  of HEAD and from this tree, normalised the whitespace, and mapped the old class names to the new
  ones. The only difference was one trailing space inside the `<select>` tag. The Skills tests
  changed only in class names (`sed` over ten test files).

## The third URL level

- `PageSection` gained `views` (slugs) and `view_key` (the context key the fragment reads). The
  Spells section declares `views=SPELL_VIEW_SLUGS, view_key="spells_tab"`.
- `GET /ui/page/{slug}/{tab}/{view}` (`page_tab_view`) calls `_render`, which first runs
  `_section_or_404` and then `_view_or_404`. The second needs a WP98 composite page, a section of
  that page, and a view the section declares. So `/ui/page/skills/combat/x` (a view-tab page) and
  `/ui/page/magic/talent/combat` (a section without views) are 404s.
- `_shell_context` sets `context[section.view_key] = view` after the sub-tab is resolved. Without
  a view, the fragment's own default (the first category) applies, so the bare sub-tab URL, a
  nav click and a remembered Spells sub-tab all open on Combat. Nothing remembers the view.
- **The slugs live in `routes/spells.py`** (`SPELL_CATEGORY_VIEWS`, derived from the catalog's
  category order: Combat, Detection, Health, Illusion, Manipulation, Rituals). `shell.py`
  imports them. The route can't import `shell.py` (the same cycle WP148 hit), and
  `submit_spells` validates `spells_tab` against them (`spell_view`: unknown → Combat).
- The view strip's links target `#page` with `hx-push-url`, so they behave like the Skills tabs:
  each one is a fresh page render, and history back walks the views.

## Fragment and route

- `_spell_selection.html`: the `<details>` wrappers, the error/stale lines above the controls, the
  two budget sentences, the Show select and the Update button are gone. In order, it now has the
  strip, the form (a hidden `spells_tab`, then one `spells-panel` per category, all but the current
  one `hidden`), and the messages (`.spells-messages`). The wrapper is `class="spells-page"`
  instead of `.panel`, as on Qualities. Checkboxes are `id="spell-<guid>"`, with the translated
  spell name as their `aria-label`, since they had no label before. The "Known" column header
  replaces "Select".
- **No heading inside the fragment.** The old `<summary>` heading "Spells" went with the
  `<details>`. The Magic sub-tab strip directly above already says Spells, so a third "Spells"
  between the two strips would be clutter.
- `_spell_selection_context` builds `spell_panels`, `spell_tab_items`, `spell_counters_start`
  (F, C) and `spell_counters_end` (Ka), plus `spells_tab`. `spell_rows`, `spells_selected`,
  `spell_max_known` and the three `spell_karma_*` keys are gone, because nothing else read them.
  The character sheet has its own `spell_karma_cost`. `spell_budget` and `spells_remaining`
  stay, because the resource panel reads them.
- Counters, each as `remaining/of`:
  - **F** is `max(free − known, 0)` over the free spells. It is floored as the phase file says, so
    it never takes the overspent highlight. Spells past the free ones cost Karma; they aren't an
    overspend.
  - **C** is `Magic × 2 − known` over `Magic × 2`, counted on the posted set. So the response that
    rejects a ninth spell shows C at −1/8, highlighted, with the error under the form.
  - **Ka** is `character.karma_remaining` over 25, the resource panel's figure. After a rejected
    post it still shows the committed figure.
  - The `<abbr>` titles reuse legacy `String_FreeSpells` ("Free Spells"), `MessageTitle_SpellLimit`
    ("Spell Limit") and `String_Karma`.
- `submit_spells` reads `spells_tab` before the casts-spells gate, so even the empty response keeps
  it. The POST contract (`spell_id` checkboxes) is unchanged.

## Filtered and Known: left out

The WP entry offered a choice: list Filtered and Known as disabled tabs with no link, or leave them
out. **I left them out.** A disabled tab needs a reason in its `title` (the macro renders
`disabled_reason_key`), so it would have meant a temporary i18n key that WP152 deletes again.
WP152 adds the two slugs to `SPELL_VIEW_SLUGS` and two items to the strip. The 404 test lists
`/ui/page/magic/spells/filtered` as unknown for now, and WP152 changes it.

## Traps hit

- `pytest -n` isn't available here (no xdist). The full suite takes about 90 s serially.
- Editing templates while the full suite ran in the background gave one spurious failure in
  `test_open_character_wp138.py`, which passes on its own. Don't edit while the suite runs.
- The macro's output isn't indented to match its call site, so the counter partial's `</div>`
  lands at column 0. Any test regex that ends a fragment at `\n</div>` stops early. The
  composite-page test still holds, because it only asks whether the fragment has content.
