# WP22 — Offer more qualities: verified-inert flavor picks + the Limit-bonus trio

Status: complete
Ref: [Implementation Plan.md](../Implementation%20Plan.md) — Phase H, WP22.

## Goal

Widen the offered SR5 quality catalog beyond WP8's 3 (Catlike, Double-Jointed, Natural Athlete),
without ever offering a quality whose real mechanical effect would be silently dropped — per
`chummer5.data.qualities`'s own stated rule that MVP never partially applies a quality's effects.
Two tranches named directly in the Implementation Plan (the Indomitable trio via a new `FLAT_BONUS`
shape; 8 verified-inert qualities via a new `NO_EFFECT` classification), plus a rulebook-research
pass over the ~20 remaining `<selecttext>`-only SR5 qualities to determine, case by case, whether
any of those are also safely offerable.

## Log

### 2026-07-19 — Confirming the Indomitable trio's `<bonus>` shape and the `<limit>`/`<includeinlimit>` combo doesn't need new validation

Read `qualities.xml` directly for Indomitable (Mental)/(Physical)/(Social): each is
`<bonus><mentallimit>1</mentallimit></bonus>` (etc.) — a single bare-numeric leaf tag, no
`<condition>`, structurally the same "flat, unconditional, feed-straight-into-the-Improvement-engine"
shape `<specificskill>`/`<specificattribute>` already cover, just untargeted (only one Mental/
Physical/Social Limit per character, mirroring `chummer5.engine.derived`'s existing `_GLOBAL_TARGET`
sentinel for the same reason). Each entry also carries `<limit>3</limit>` and an `<includeinlimit>`
cross-referencing the other two names — traced in `legacy/Chummer/Backend/Static/SelectionShared.cs`
(`includeinlimit` handling, ~line 505): this is the legacy data's way of capping "at most 3 combined
levels across these 3 named entries" for a quality that's conceptually one repeatable pick split into
3 separate XML entries. Confirmed this needs **no new validation code**: `create_quality_selection`
already rejects selecting the same quality id twice, and there are only 3 distinct ids to begin with,
so the maximum achievable combined selection (1 each = 3 total) already equals the cap exactly — the
rule is satisfied by construction, not enforced explicitly. See `spec/rulebooks/learnings.md`'s WP22
entry for the rulebook citation (p. 75: "+1 increase... up to three levels... in any way he
chooses").

### 2026-07-19 — Verifying the 8 Tranche-2 "no effect" qualities, and why the classification is name-gated rather than shape-gated

Per the Implementation Plan's own instruction, confirmed each of Gearhead/Guts/Juryrigger/Natural
Hardening/Low-Light Vision/Thermographic Vision/Simsense Vertigo/Unsteady Hands has an empty
`<bonus/>` in `qualities.xml` **and** ran `grep` across `legacy/Chummer/Backend/**/*.cs` for each
quality's exact name — zero hits for any of the 8, confirming the legacy engine itself treats these
as pure narrative flags with no `Improvement`-equivalent side effect, not just "MVP doesn't happen
to support this shape yet." Cross-checked their actual rulebook text (p. 66, 74-76, 83, 87) to
confirm *why*: each effect lands on a subsystem this project's engine has zero representation of
(vehicle combat, fear-resistance tests, Matrix-attack resistance, lighting-condition perception,
AR/VR/simsense tests, called-shot combat penalties) — see `spec/rulebooks/learnings.md`'s WP22 entry
for the specific citations.

**Found while doing this: 15 SR5 qualities total have an empty `<bonus/>`, not 8.** The other 7
(Astral Chameleon, Focused Concentration, Human-Looking, Astral Beacon, Distinctive Style, Insomnia
(Basic), Insomnia (Full)) are excluded from MVP's offered catalog for reasons unrelated to their
bonus shape — magic-gated, Notoriety-gated, or needing a "required metatype"/"mutually exclusive
quality" check this WP explicitly didn't build (see Implementation Plan's WP22 entry, "Deliberately
deferred" bullet). This means `BonusSupport.NO_EFFECT` **cannot** be "any quality with an empty
`<bonus/>`" — that would silently offer Human-Looking (needs a metatype gate) and the Insomnia pair
(needs mutual-exclusion) with no such check ever applied. Implemented `_classify_bonus` to check the
quality's **name** against an explicit `_VERIFIED_NO_EFFECT_NAMES` frozenset first, before falling
through to the existing empty-`<bonus/>` → `NOT_YET_SUPPORTED` path — added
`test_unverified_empty_bonus_quality_stays_not_yet_supported` (Human-Looking) specifically to guard
against this WP or a future one collapsing the distinction back to a shape-only check.

### 2026-07-19 — The rulebook-research pass over the ~20 remaining `<selecttext>`-only qualities: none added

`pdftotext -layout` read of every remaining SR5 quality whose sole `<bonus>` child is
`<selecttext/>` (24 total by direct XML count; 8 are Allergy's variants, already correctly excluded
elsewhere as "a toxin/pathogen system this project doesn't model" per the Implementation Plan's own
aside, so out of this pass's real scope — leaving 16: Home Ground, Natural Immunity ×2, Spirit
Affinity, Code of Honor, Codeblock, Prejudiced ×6, SINner ×3, Social Stress).

**Conclusion: none of the 16 are added to the offered catalog this WP**, for two independent
reasons, both confirmed per-quality rather than assumed uniformly:

1. **Spirit Affinity** is `<required>`-gated to Aware/Magician/Mystic Adept/etc. — unreachable by
   any mundane MVP character regardless of anything else, the same bucket as the already-excluded
   Focused Concentration.
2. **The other 15** all require the player to supply a free-text "select a target" choice
   (`<selecttext>`) that's an intrinsic, non-optional part of taking the quality — which specific
   group, disease, Matrix action, or behavioral code. `chummer5.data.qualities` has no mechanism to
   capture that choice at all; building one (a real input + persistence + display flow) is a
   separate, WP-sized piece of work the Implementation Plan's own tranche framing ("verified-inert
   flavor picks," pure data-classification changes) doesn't cover. This holds regardless of how
   mechanically inert a given quality's downstream effect is — 4 of the 15 (Code of Honor,
   Codeblock, Social Stress, Natural Immunity) turned out to be just as mechanically inert to this
   engine's scope as Tranche 2's 8 (their real effects — in-play Karma loss, a Matrix-action dice
   penalty, a glitch-threshold shift, toxin immunity — all land on subsystems this project doesn't
   model), but stayed excluded anyway because the selection itself, not a numeric bonus, is what
   would be silently dropped. The remaining 11 (Home Ground, Prejudiced ×6, SINner ×4 counting
   Criminal) additionally carry real, non-trivial mechanical or narrative weight the Implementation
   Plan itself flagged as a reason for caution.

This is a genuine, documented research conclusion, not a shortfall against the acceptance criteria —
the Plan's own acceptance line only requires the offered catalog to grow "from 3/96 upward," which
Tranches 1+2 alone satisfy (3 → 14), and explicitly frames the research pass as "only add ones this
pass confirms are as genuinely inert as tranche 2's 8" rather than mandating a minimum addition
count. Full per-quality reasoning, with rulebook citations, is recorded in
`spec/rulebooks/learnings.md`'s WP22 entry so a future WP building free-text quality selections
doesn't have to re-derive which of these 16 are worth the effort.

### 2026-07-19 — A side effect worth flagging: MVP's first-ever offerable Negative qualities

2 of Tranche 2's 8 `NO_EFFECT` qualities — Simsense Vertigo (-5 karma) and Unsteady Hands (-7
karma) — are Negative category. Through WP21, MVP had never offered *any* Negative quality (WP8's 3
FLAT_BONUS qualities were all Positive), so the negative-quality karma cap in
`create_quality_selection` was real, tested rules logic that no real-data selection could actually
trigger. It still can't reach the 25-karma cap on its own (-5 + -7 = -12), so the boundary-case tests
still need synthetic data, but real content now exercises the negative-karma code path for the first
time — updated `chummer5.engine.qualities`'s module docstring to say so rather than leave the old
"MVP currently offers no Negative quality" claim stale.

## Design decisions

- **`BonusSupport` gains a third value, `NO_EFFECT`, distinct from `FLAT_BONUS`.** Keeps "has a real
  Improvement to apply" (`FLAT_BONUS`) visibly different from "verified to need no Improvement at
  all" (`NO_EFFECT`) rather than conflating the two under one "supported" label — exactly as the
  Implementation Plan specified. `mvp_quality_catalog` offers both; `apply_quality_improvements`
  needed no change at all, since a `NO_EFFECT` quality's `flat_bonuses` is `()` by construction, so
  the existing per-quality loop is naturally a no-op for it.
- **`_VERIFIED_NO_EFFECT_NAMES` is a name-gated frozenset, not a shape-based rule.** See the Log
  above — an empty `<bonus/>` alone is *necessary* but not *sufficient* for `NO_EFFECT`; 7 other
  empty-`<bonus/>` SR5 qualities stay `NOT_YET_SUPPORTED` because they need different, not-yet-built
  engine support (metatype gates, mutual exclusion). `_classify_bonus` now takes the quality's `name`
  as a parameter specifically so this check can run first.
- **Limit bonuses reuse `FlatBonus` with 3 new `target_kind` values (`"mental_limit"`/
  `"physical_limit"`/`"social_limit"`) and `target_name=""`**, rather than adding a new dataclass or
  a separate resolution path. `chummer5.engine.qualities._TARGET_KIND_TO_IMPROVEMENT_TYPE` maps each
  directly to the matching `ImprovementType`, and `character.improvements.resolve(..., "")` already
  matches `chummer5.engine.derived`'s own `_GLOBAL_TARGET` sentinel, so `mental_limit()` etc. picked
  up the new Improvements with zero changes to `chummer5.engine.derived` itself — confirmed via a
  real end-to-end manual walkthrough (Verification below), not just a unit-level Improvement-index
  check.
- **No web-layer changes.** `_quality_selection_context`/`_quality_selection.html` already iterate
  whatever `MVP_QUALITIES` contains generically (no hardcoded name/count anywhere in the route or
  template) — widening the catalog at the data/engine layer was sufficient by construction. Verified
  this holds via a real HTTP walkthrough, not just an assumption from reading the code.
- **The research pass added zero new offerable qualities beyond the two tranches**, a deliberate,
  documented outcome rather than a gap — see the Log's research-pass entry for why "verified inert
  but still excluded" (4 qualities) and "not inert" (11 qualities) both land on the same "not added"
  conclusion for different reasons, and why that's still within this WP's acceptance criteria.

## Implementation

- `src/chummer5/data/qualities.py`: `BonusSupport.NO_EFFECT` added; `_LIMIT_BONUS_TAGS` (tag →
  `target_kind` mapping for the 3 Indomitable shapes) and `_VERIFIED_NO_EFFECT_NAMES` (the 8
  Tranche-2 names) added; `_classify_bonus` now takes `name: str` as its first parameter, checks it
  against `_VERIFIED_NO_EFFECT_NAMES` before the empty-`<bonus/>` check, and recognizes
  `<mentallimit>`/`<physicallimit>`/`<sociallimit>` leaf tags as a third flat shape alongside
  `<specificskill>`/`<specificattribute>`; `_parse_quality` passes the quality's own name through.
  `FlatBonus`'s docstring updated for the 3 new `target_kind` values. Module docstring rewritten to
  describe all 3 `BonusSupport` values.
- `src/chummer5/engine/qualities.py`: `_TARGET_KIND_TO_IMPROVEMENT_TYPE` gains `"mental_limit"` →
  `ImprovementType.MENTAL_LIMIT` (and the Physical/Social equivalents); `mvp_quality_catalog` widened
  from `bonus_support == FLAT_BONUS` to `bonus_support in (FLAT_BONUS, NO_EFFECT)`. Module docstring
  updated for the new 14-quality offered set and the first-ever offerable Negative qualities.
- `src/chummer5/engine/improvements.py`: `ImprovementType`'s docstring updated — the 7
  derived-stat-only improvement types are no longer all "nothing produces these yet" now that
  Indomitable produces 3 of them.
- `tests/unit/test_qualities.py`: `test_supported_vs_unsupported_counts_are_visible` updated for the
  new 6/8/82 split; new tests for the Indomitable trio's `FlatBonus` shape, a verified-`NO_EFFECT`
  quality (Gearhead), and the shape-vs-name-gating distinction (Human-Looking stays
  `NOT_YET_SUPPORTED` despite its own empty `<bonus/>`).
- `tests/unit/test_quality_selection.py`: `mvp_quality_catalog` test widened to the real 14-name set
  (renamed accordingly); new test asserting every WP22-researched-and-excluded quality (Astral
  Beacon/Chameleon, Focused Concentration, Gremlins, plus all 16 of this WP's own researched
  `<selecttext>` qualities) stays excluded; new tests: Indomitable (Mental) alone raises
  `mental_limit()` by 1 via a real `create_character`/`apply_quality_improvements`/`mental_limit()`
  round trip (not just the Improvement index), all 3 Indomitable qualities together raise all 3
  Limits and cost exactly 24 karma (under the 25 cap), and a `NO_EFFECT` quality (Gearhead) adds zero
  Improvements while still costing karma.
- `spec/rulebooks/learnings.md`: new WP22 entry — Indomitable's rulebook citation, and the full
  per-quality reasoning for why each of the 16 researched `<selecttext>` qualities stays excluded.
