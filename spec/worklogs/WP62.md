# WP62 — Split web/app.py into per-chargen-step route modules

Status: complete
Ref: [Implementation Plan.md](../Implementation%20Plan.md) — Phase R, WP62.

## Goal

Execute the target shape WP58's audit decided (`spec/plan/phase-r-architecture-cleanup.md`): split
the 4,499-line `chummer5.web.app` into `web/catalogs.py`, `web/forms.py`, and one
`web/routes/<step>.py` `APIRouter` module per chargen step, with `web/app.py` shrinking to just
`create_app()`. Pure move/reorganization — no behavior change, no template edits.

## Log

### 2026-07-27 — Mapped every function/route to its target module before moving anything

Used Python's `ast` module (not manual line-counting) to get exact line ranges for every top-level
`def`/assignment in `app.py`, then a second pass over `create_app()`'s own body to enumerate its 21
nested route closures with their decorators. Cross-referenced every helper's call sites (`grep -n`
for each name) to confirm which route(s) actually used it before assigning a home — this caught a
few cases the audit's own prose summary didn't spell out:

- `_relink_metatype_qualities`/`_relink_contact_selection` are called from **both**
  `submit_priorities` and `submit_attributes` (2 different step modules), not just one. Gave them a
  home in the module they're conceptually about (`qualities.py`, `contacts.py` respectively) and had
  `attributes.py`/`priorities.py` import them from there — no cycle, since neither qualities.py nor
  contacts.py needs anything back from attributes.py/priorities.py.
- `_remove_adept_power_improvements` (owned by `powers.py`) and `_remove_foci_improvements` (owned
  by `foci.py`) are both called from `talent.py`'s `_replace_committed_talent` (a Talent change
  invalidates committed powers/foci) — same cross-import pattern, same cycle-safety argument.
- `_display_karma_to_nuyen` (renamed `display_karma_to_nuyen`, dropping the leading underscore now
  that it's cross-module public API) is used by **four** step modules (resources, lifestyle,
  cyberware, foci), not the two the audit's own "genuinely generic, 2+ callers" example
  (`_parse_points`/`_parse_specializations`) named — added it to `forms.py` alongside those two,
  since the same "used by more than one step" criterion applies.
- `_offered_skills`/`_offered_skill_groups` (also renamed, same reasoning) are catalog-derived
  filters over `MUNDANE_SKILLS`/`_MAGICAL_SKILLS`, so they moved to `catalogs.py` alongside those
  constants rather than either skills.py or a route module — used by `skills.py`'s context builder,
  `skills.py`'s own route, and `character.py`'s sheet context.
- `resolve_session` (a `create_app()`-local closure through WP61) moved to `chummer5.web.session`,
  not `catalogs.py` — it's built directly out of `SessionStore`/`SESSION_COOKIE_NAME`, both already
  defined there, and every route module needs it; putting it in `catalogs.py` instead would have
  worked too, but colocating with what it's built from seemed like the more legible home. The
  `Jinja2Templates` instance (`templates`) went to `catalogs.py` instead, since it's used by every
  route module and has no natural non-web-layer home the way `resolve_session` does.

Confirmed via the audit's own "which module hosts `_character_sheet_context` vs.
`_chargen_body_context`" open question: put `_chargen_body_context` in `priorities.py` (its only two
callers, `index`/`submit_priorities`, both already live there) and `_character_sheet_context` in a
new `routes/character.py` alongside `download_save`/`load_save`/`import_chum5_route` (its own three
callers) — matches the audit's own suggested placements exactly, no surprises once the full call-site
map was in hand.

### Verification

`ruff check`/`mypy` clean across the new `web/` tree (one real mistake caught by mypy:
`load_cyberware` is `chummer5.data.cyberware`, not `chummer5.engine.cyberware` — a typo introduced

Also ran a live `uvicorn` smoke test (not just the test suite): started the app, drove a full mundane
chargen through raw HTTP (`urllib` + `http.cookiejar` for session-cookie handling) — priorities →
attributes → talent → skills → knowledge → qualities → contacts → resources → lifestyle → cyberware
→ foci → character sheet → save download — every step returned 200 and the downloaded save JSON
round-tripped correctly.

`web/app.py`: 4,499 → 104 lines.
