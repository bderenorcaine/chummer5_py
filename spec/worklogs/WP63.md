# WP63 — Unify submit_attributes onto the dataclasses.replace() shape

Status: complete
Ref: [Implementation Plan.md](../Implementation%20Plan.md) — Phase R, WP63.

## Goal

Give `submit_attributes` (`chummer5.web.routes.attributes`) the same WP19 treatment
`submit_priorities` already has: build its new `Character` via `dataclasses.replace(previous, ...)`
instead of a fresh `create_character()` call, retiring the "one new relink call per WP" accretion
`spec/plan/phase-r-architecture-cleanup.md`'s WP58 audit (Finding 2) documents.

## Log

### 2026-07-27 — Confirmed `create_character` is still needed, just not as the thing built on

`create_character` does two jobs at once: validate the submitted `attribute_points` (raises
`ValueError` on an invalid spend) and construct a `Character`. WP63 only needed the first job —
kept the call (so every existing validation error message/behavior is unchanged) but stopped using
its returned, always-fresh-and-empty `Character`. The actual new `Character` is now
`dataclasses.replace(previous, attribute_points=...)`, built right after the validation call
succeeds, then fed into `create_karma_attribute_points` exactly like the old fresh `character` was
(that function reads `character.attribute_points.get(code, 0)` directly, so it does need the
just-validated points already set on whatever `Character` it's given — confirmed by reading its
body before assuming `replace()` could happen any later in the function).

### Confirmed which of the five relink calls become dead code

Grepped every call site of `_relink_quality_improvements`, `_relink_magic_selection`,
`_relink_cyberware_selection`, `_relink_bioware_selection`, `_relink_foci_selection` before deleting
anything — all five were called from exactly one place each (`submit_attributes`), with no other
caller anywhere in `src/` or `tests/`. Deleted all five function definitions outright rather than
leaving unused helpers behind, per the WP's own instruction. `_relink_metatype_qualities` and
`_relink_contact_selection` stay, unchanged in behavior — confirmed by reading both: `_relink_
metatype_qualities` always removes-then-reapplies `character.metatype_qualities`'s own METATYPE
Improvements before resolving them fresh from `character.metatype`, so calling it on a
`replace()`-carried `Character` (metatype unchanged, `metatype_qualities` and its Improvements
already present) is a genuine no-op — safe, matching the audit's own prediction, not just
"harmless by luck." `_relink_contact_selection` recomputes `ContactSelection` from `character
.attribute_value("CHA")`, which an EDG/attribute-point edit can genuinely change, so it keeps doing
real work here exactly as it did before.

Deleting the five functions left two unused imports to clean up: `apply_power_improvements` in
`talent.py` (only used inside the now-deleted `_relink_magic_selection`; `create_magic_selection`
and `apply_magic_skill_grant_improvements` from the same import block are still used elsewhere in
that file, so only `apply_power_improvements` came out). `cyberware.py`/`foci.py`/`qualities.py`
needed no import changes — `apply_cyberware_improvements`/`apply_bioware_improvements`/`apply_foci_
improvements`/`apply_quality_improvements`/`apply_mentor_spirit_improvements` are all still used by
each module's own `_replace_committed_*` sibling function.

### Docstring/comment cleanup for the now-deleted functions

Several docstrings elsewhere referenced the deleted functions by name (as "mirrors X" or "see X's
docstring for why" cross-references) and would have gone stale — updated instead of left dangling:
`_relink_metatype_qualities`'s own docstring (qualities.py, no longer contrasts itself with the
deleted `_relink_quality_improvements`), `submit_priorities`'s inline comment (priorities.py,
explained why calling `_relink_quality_improvements` there would double-apply a bonus — reworded to
describe the concept without naming a function that no longer exists), `_spell_selection_context`'s
docstring (spells.py, referenced `_relink_magic_selection` by name), and `_apply_built_character_to_
session`'s docstring (character.py, cited `_relink_quality_improvements`'s docstring "for why that
matters elsewhere"). Two test docstrings got the same treatment: `test_web_character_sheet.py`'s
`test_a_loaded_qualitys_bonus_survives_a_later_attribute_edit` and `test_web_magic.py`'s `test_
attribute_resubmission_preserves_the_carried_forward_magic_selection` — both still pass unchanged
(their assertions never depended on the internal mechanism), but their docstrings described the
pre-WP63 relink-based reasoning as if it were still current.

### New regression test proving the bug class is now structurally impossible

Added `test_attribute_resubmission_preserves_magic_cyberware_and_bioware_together` to
`test_web_magic.py`, per the WP's own acceptance bar: builds an Adept (Talent letter B, Resources
letter A for budget headroom — Synthetic Full Arm + Enhanced Articulation cost 44,000¥ together,
past what letter E's 6,000¥ affords), buys an Adept power (Improved Potential (Physical)), a
cyberware item with a `PHYSICAL_CM` flat bonus (Synthetic Full Arm), and a bioware item with a
`PHYSICAL_LIMIT` flat bonus (Enhanced Articulation), then submits an attribute edit and confirms
every one of those three selections' Improvements survives on the character sheet — Adept type,
Magic rating (correctly reduced from 6 to 4 by `ceil(1.3)` Essence lost, proving the essence-driven
Magic-loss calc still sees the surviving cyberware/bioware after the edit, not just that the items'
names are still listed), granted skill's dice pool, both catalog items' presence, remaining Essence,
and the combined physical_limit total (base 2 + power's +1 + bioware's +1 = 4). Caught one arithmetic
mistake while writing it: `math.ceil(1.3) == 2`, not 1 — first draft asserted "Magic rating: 5",
corrected after running the test and reading the actual rendered sheet rather than trusting mental
math.
