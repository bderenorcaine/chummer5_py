# WP73 — Priority-built cyberware + bioware Essence-stacking fixture

Phase S. Second fixture-authoring WP, the first to consume WP72's synthetic harness for a subsystem
*interaction*. Closes coverage gaps **G1** (a Priority-built character bearing cyberware, Essence
computed from real implants) and **G2** (cyberware + bioware Essence costs stacking against the one
shared pool) — see `phase-s-test-fixtures.md` §2. No real `.chum5` fixture is both Priority-built and
cyberware-bearing, and none combines cyberware with bioware at all (the 8 cyberware-bearing curated
fixtures are all SumtoTen and carry zero bioware), so this interaction had never had a whole-character
fixture.

## Goal

Extend `SyntheticCharacter`/`build_synthetic()` with cyberware + bioware inputs (the WP72-documented
"add your field + wiring together" extension pattern), then author one legal, fully-spent mundane
Priority build carrying ≥1 cyberware and ≥1 bioware item — proving the shared Essence pool and the
Essence-derived stats end to end through the *real* engine, every asserted number cited to
`cyberware.xml`/`bioware.xml`/`priorities.xml`/`learnings/phase-d.md`.

## Log

### Harness extension (tests-only, no `src/` change)

Like WP72, this is a tests-only WP. The two new input fields are name-keyed lists resolved to catalog
ids in `build_synthetic()`, mirroring the existing skill/quality name-keying:
- `SyntheticCharacter.cyberware: tuple[str, ...]` / `bioware: tuple[str, ...]` — both default `()`
  and both may repeat an item (duplicate purchases are legal, per `chummer5.engine.cyberware`).
- `build_synthetic()` resolves the Resources-priority nuyen from `fixture.resources_letter` and drives
  the *real* selection functions in the documented **cyberware-first, bioware-second** order:
  `create_cyberware_selection(..., nuyen_budget)` then `create_bioware_selection(..., nuyen_budget -
  cyberware.nuyen_spent, other_essence_spent=cyberware.essence_spent)`. This is exactly the shared-pool
  evaluation order `chummer5.engine.bioware`'s own docstring settled on, so the fixture exercises the
  same path the web/save layers do — including the "a combination only invalid once *both* are counted
  is caught on the bioware call" guarantee. Both `apply_*_improvements` then land their Essence (and
  any flat bonus) in the character's already-linked `ImprovementIndex`.

### New metric keys — the shared-pool split made explicit

`resolve_metric` gained `cyberware:essence_spent`, `cyberware:nuyen_spent`, `bioware:essence_spent`,
`bioware:nuyen_spent` — reading straight off the two committed selections. This lets the fixture assert
the G2 stacking *per source* (cyberware 3.1 + bioware 0.5), not only via the combined `essence` (2.4),
so a regression that mis-attributed cost between the two pools — but happened to keep the sum right —
still fails. `assert_fixture`'s Essence comparison was generalized from "only the `essence` key" to
"any `Decimal`-valued metric on either side," covering the new `*:essence_spent` keys through the same
`_decimal` normalization.

### The fixture — Dražen "Rebar" Kovač, Ork street samurai

A legal, fully-spent Ork samurai; the team's muscle (WP72's Cheshire is the infiltrator, per the §5
roster). Priorities **Attributes A / Heritage B / Resources C / Skills D** (Talent forced to E).

**Priority-letter constraint that shaped the build:** Ork is only offered at Heritage A/B/C — never D
(Human/Elf only). With Attributes A and a low letter forced onto Skills/Resources, Heritage B is the
best an Ork can take here; its 4 special-attribute points lift Edge off its floor (1 → 5). D landed on
Skills (22 points, 0 groups) — a focused combat samurai, not a broad one.

Hand-derived, all cross-checked live against the loaders and re-verified by building through the engine
before writing the literal:
- Attributes (24 primary, all spent; EDG +4 from 4 special pts): BOD 6, AGI 6 (natural max — the only
  one), REA 5, STR 6, CHA 2, INT 5, LOG 2, WIL 5, EDG 5.
- Skills (22, all spent): Automatics 6, Blades 4, Pistols 3, Perception 3, Intimidation 2, Sneaking 2,
  Escape Artist 1 (→ **2** with the Enhanced Articulation bioware bonus), Gymnastics 1.
- Cyberware (55,000¥, Essence **3.1**): Obvious Full Arm (1.0, +1 Physical CM — the one modeled
  cyberware bonus), Bone Lacing (Titanium) (1.5), Spurs (0.3), Datajack (0.1), Smartlink (0.2).
- Bioware (41,000¥, Essence **0.5**): Enhanced Articulation (0.3, +1 Physical Limit AND +1 Escape
  Artist), Platelet Factories (0.2). Total augmentation nuyen 96,000 of the 140,000 Resources-C pool.
- Essence: 6 − 3.1 − 0.5 = **2.4** (strictly positive → legal). `ceil(2.4) = 3` feeds `social_limit`.
- Derived: initiative 10 (REA 5 + INT 5), init dice 1; physical limit **10** (base 8 + Indomitable 1 +
  Enhanced Articulation 1 — two `PHYSICAL_LIMIT` sources stacking); mental limit 5; social limit 4;
  physical CM **12** (base 11 + Obvious Full Arm 1); stun CM 11.
- Karma: positives 18 (Indomitable (Physical) 8 + Guts 10) − Code of Honor 15 = **3** spent, 22 left.

## Design decisions

- **Flat-catalog reality vs. the team-role blurb.** §5's "wired reflexes cyber + muscle toner bio"
  example is illustrative — both are rating-scaled and therefore excluded from the flat WP31/WP45
  catalogs. Used flat equivalents that still make a coherent samurai (a cyberarm, titanium bone lacing,
  spurs, datajack, smartlink; enhanced articulation + platelet factories) and, more importantly, still
  hit every mechanic the WP must test. Flagged the discrepancy in the phase file so it doesn't read as
  an oversight.
- **Chose items that exercise all three modeled augmentation bonus paths, not just Essence.** Obvious
  Full Arm → the one `FLAT_BONUS` cyberware type (`PHYSICAL_CM`); Enhanced Articulation → the
  skill+limit bioware `FLAT_BONUS` (`SKILL` + `PHYSICAL_LIMIT`); the rest are `NO_EFFECT`/
  `NOT_YET_SUPPORTED` so only their Essence/nuyen cost is content (the Project Overview's augmentation
  posture). Two `PHYSICAL_LIMIT` sources (Indomitable quality + Enhanced Articulation bioware) were
  deliberately stacked to prove independent-source additivity on one `ImprovementType`.
- **Per-source Essence metrics, not only the combined total** — a mis-attribution that keeps the sum
  right is a real regression shape the combined `essence` alone can't catch (see Log).
- **Coherent, complementary teammate, not a re-skin of Cheshire** — CHA 2 / LOG 2 by design (the Face
  and Decker fill those), matching §5's "sanity-check the new runner against the roster table" note.

## Traps hit

- **Ork ≠ Heritage D.** First priority layout tried put Heritage on D; `build_synthetic` (rightly)
  rejected it — Ork isn't offered below Heritage C. Reworked to Attributes A / Heritage B / Resources C
  / Skills D, which also happens to be a better samurai (Edge 5 instead of 1).
- **`ruff` line-length (100)** on the prose comment block and two long citation strings — reflowed by
  hand (`ruff format` doesn't rewrap comments/strings), same trap WP72 recorded. No logic impact.
- No PDF lookup needed: every formula and budget this fixture asserts was already extracted in
  `learnings/phase-d.md` or lives in the catalogs/`priorities.xml`, so no new `learnings.md` entry and
  no `decisions-log.md` entry were warranted.
