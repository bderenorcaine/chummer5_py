# WP76 — Sum-to-Ten whole-character fixture

Phase S, and the last of its fixture-authoring list. Closes coverage gap **G7** — the Sum-to-Ten
build method (WP44's sibling letter-assignment rule) combined with a layered subsystem — see
`phase-s-test-fixtures.md` §2. Lands the team's fifth and final runner, the Decker.

The gap is easy to misread as already covered: 33 of the 34 legacy `.chum5` fixtures are
`buildmethod = SumtoTen`. But WP4 only ever *reads finished values* out of those files — none of them
is rebuilt through this engine, and not one set of letters is ever run through this project's own
`chummer5.engine.build_method` validation. Before this WP, Sum-to-Ten had unit tests
(`tests/unit/test_build_method.py`) and the web route on top of them, and every synthetic fixture was
a Priority build. So the gap was real: no whole character had ever been *built* Sum-to-Ten here.

## Goal

Make WP72's synthetic harness build-method-aware (its letter validation was hard-coded to Priority's
bijection), then author one legal, fully-spent Sum-to-Ten character carrying a cyberware layer, with
every asserted number cited.

## Log

### Harness extension (tests-only, no `src/` change)

Like WP72-75, tests-only — the engine already had everything needed.

- `SyntheticCharacter` gains one field: `build_method` (default `PRIORITY_BUILD_METHOD`, so all four
  existing fixtures are unchanged).
- `build_synthetic()`'s inline letter check moved into a new `_validate_letters(build_method, letters)`
  helper that mirrors `chummer5.web.routes.priorities.submit_priorities` — Priority's bijection,
  Sum-to-Ten's `validate_sum_to_ten_total`, and an explicit raise for an unrecognised method rather
  than a silent fallback to either real rule. That route is the *only* place the real app validates
  letter-assignment shape either (`create_character` never has — it just reads budgets off whatever
  letters it's handed), so the fixture path is now held to exactly the same rule a player submission
  is, in the same one place per method.
- **No new metric key**, and that's the finding worth recording: `Character` has no `build_method`
  field at all (it's session/save-format state — `chummer5.web.session`, WP44), and nothing downstream
  of the letters differs between the two methods — both read the same `priorities.xml` rows. So a
  Sum-to-Ten fixture's letter assignment is asserted *by construction* (`build_synthetic` raises
  unless the five letters total exactly 10), and the dedicated test additionally asserts the same five
  letters are rejected under `PRIORITY_BUILD_METHOD`. Inventing a metric key would have meant plumbing
  the fixture (not the `Character`) into `resolve_metric`, i.e. widening the harness's shape to assert
  something the harness already enforces.

### The fixture — Bakari "Nullsec" Osei, Dwarf decker (they/them)

Sum-to-Ten letters **Heritage B (3) / Skills B (3) / Attributes C (2) / Resources C (2) / Talent E
(0) = exactly 10**. Every figure hand-derived first, then verified against the engine in a scratch
prototype before the literal was written (the WP74/WP75 practice — all ~45 asserted values matched the
hand derivation on the first run):

- Attributes (Attributes C = 16 primary, all spent; Heritage B/Dwarf = 4 special, all spent):
  BOD 3, AGI 2, REA 4, STR 3, CHA 2, INT 5, **LOG 6** (their one attribute at its natural maximum),
  WIL 4 → 5 via Karma, EDG 5.
- Skills (Skills B = 36 + 5 group, all spent): group Electronics 5 → Computer/Hardware/Software all
  at 5; individual Hacking 6, Cybercombat 5, Electronic Warfare 4, Perception 4, Sneaking 3, Pistols
  3, Etiquette 3, Con 3, First Aid 2, Gymnastics 2, Palming 1.
- Cyberware (8,000¥ of Resources C's 140,000): Cyberdeck 0.4, Datajack 0.1, Image Link 0.1, Sound
  Link 0.1 → Essence 6 − 0.7 = **5.3**. Mundane, so no Essence→Magic interaction (WP74's job); here
  Essence only feeds the Social Limit's `ceil(ESS)` term.
- Qualities: Natural Hardening 10 + Indomitable (Mental) 8 positive; **SINner (Corporate) 25**
  negative — the Negative cap hit by a *single* quality. Net −7, so the Step Seven pool is 32.
- Step Seven, all 32 spent (`karma_spent` 25, `karma_remaining` **0**): WIL 4 → 5 for **25**
  (new rating 5 × 5) and a Hacking specialization "Devices" for **7** (flat).
- Derived: initiative 9, physical limit 5, mental limit **9** (8 + Indomitable (Mental)), social limit
  5, physical CM 10, stun CM 11, Hacking pool **14** (6 + LOG 6 + 2 spec).

## Design decisions

- **Two repeated letters, on purpose.** `B/B/C/C/E` is the point of the fixture: it buys Skills B
  *and* Heritage B (Dwarf, 4 special points) *and* Resources C at the price of a merely-adequate
  Attributes C — a trade Priority's one-letter-each rule cannot express at all. A Sum-to-Ten fixture
  that happened to use five distinct letters would total 10 (4+3+2+1+0) and pass, while testing
  nothing Priority doesn't already cover. The test asserts the repeat explicitly (`len(set(letters)) <
  len(letters)`) so a future edit can't quietly turn it into a permutation.
- **Dwarf, and REA held at 4.** Dwarf is the last SR5-core metatype the synthetic set didn't use, and
  the only one whose **REA maximum is 5, not 6** (`metatypes.xml`). REA 5 would put a second attribute
  at its natural maximum alongside LOG 6 — illegal per Step Two, and it would also make the WIL Karma
  raise raise, since `create_karma_attribute_points` re-checks that rule whenever a Karma spend
  touches a Mental/Physical attribute. So the metatype choice and the Karma spend constrain each
  other; the citation for `attr:REA` records why the 4 isn't just an aesthetic choice.
- **The Negative cap hit by one quality.** SINner (Corporate) at 25 is the largest Negative in the SR5
  core catalog and had no fixture. Cheshire/Rebar/Wren all reach their Negative total with two or
  three qualities; this one sits exactly on `QUALITY_KARMA_LIMIT` with a single entry, which is the
  boundary case the cap check would most plausibly get wrong (`>` vs `>=`).
- **A Karma specialization that breaks *nothing*.** WP75 covered the group-breaking side (a Karma
  raise/specialization on a member of a *group-purchased* group). Here Hacking is a Cracking member,
  but Cracking was never group-bought, so `broken_groups` is empty — the complement, and the case
  where an over-eager implementation would wrongly report a break. Buying Hacking/Cybercombat/EW
  individually at uneven ratings (6/5/4) also exercises strict skill groups from the other direction:
  it's only legal *because* the group has no points.
- **Cyberware layer, not magic.** The WP offered either; cyberware was the right pick because the
  magic side is already covered twice (WP74/WP75) and because an implanted rig is what a decker
  actually carries. It keeps this fixture's new content squarely on the build method.
- **Team fit (roster §5).** Fills the Matrix role Cheshire structurally can't (Simsense Vertigo) and
  leans on the LOG the Sam (LOG 2) and Cheshire (LOG 3) don't have. Deliberately AGI 2 / CHA 2 — not a
  second climber, not a second face, per §5's own instruction.

## Traps hit

- **Field ordering in a frozen dataclass.** First attempt put `build_method` next to `metatype` for
  readability, which breaks `@dataclass` (a defaulted field can't precede non-defaulted ones). It
  belongs at the head of the defaulted block instead; the fixture literals name it as a keyword
  anyway, so ordering is documentation-only.
- **"Cerebral booster" isn't offerable.** Phase S's WP76 blurb suggested "datajack + cerebral
  booster"; Cerebral Booster is *rating-scaled bioware*, so it's outside WP45's flat-cost catalog —
  the same illustrative-only mismatch WP73 hit with "wired reflexes + muscle toner". Checked the
  loaded catalogs rather than trusting the blurb; used flat equivalents (Cyberdeck/Datajack/Image
  Link/Sound Link) and recorded the mismatch in the phase file so it isn't re-hit.
- **`ruff` isort puts `chummer5` *after* `tests`** in test modules — `chummer5` is known-first-party
  (src layout) while `tests` lands in third-party. `ruff check --fix` sorted it; worth knowing before
  hand-placing an import in a test file that imports both.
- **`ruff` line-length (100)** on the prose block and long citation strings, as in every prior Phase-S
  WP (`ruff format` won't rewrap comments/strings). Pre-existing `ruff format` drift elsewhere under
  `tests/` was left alone; the three files this WP touched are clean.
- No PDF lookup needed. Sum-to-Ten's point table and exact-equality target are legacy-C#-sourced
  (`SelectMetatypePriority.cs`) with **zero** core-rulebook hits — already established by WP44 and
  recorded in `learnings.md`; every other figure is `priorities.xml`/`metatypes.xml`/`cyberware.xml`
  data or an already-extracted `learnings/phase-d.md` / `phase-o.md` formula. So no new
  `learnings/` entry and no `decisions-log.md` entry.
