# WP85 — Land the player-authored save as the project's first on-disk save-format fixture

Phase S, reopened. The first of four WPs (WP85-88) triggered by a character that arrived from
outside the plan: a save file in *this project's own format*, built by a player through the web UI
rather than derived from a coverage table. See `phase-s-test-fixtures.md` §6 for why one file was
worth reopening a phase marked complete.

## Goal

Get the character into the repo as *data*, and get a regression guard onto the save format — which
has never had one — before WP86-88 start converting it into a synthetic fixture.

## Log

### The gap this closes is narrower and sharper than "the save format is untested"

`tests/integration/test_save_format_fixtures.py` has round-tripped `save_format` since WP11. What it
does is build a `CharacterSave` in code, serialize it, read it back, and compare. That is a real test
and it catches real bugs — but it can only ever prove **the writer and the reader agree with each
other**. It is structurally incapable of catching a change that leaves both self-consistent while
breaking a file an older build already wrote, because no such file participates in it.

A checked-in file written by an older build does participate. That is the whole content of this WP:
`razorboy.json` is the first artifact in this repo that the save format has to keep being able to
read, as opposed to keep agreeing with itself about.

### Verified before writing anything: it loads clean today

Ran the file through `from_json` + `build_character` with the same twelve catalogs
`chummer5.web.routes.character.load_save` passes, and checked every figure §6 claims about it. All
six matched on the first run — Essence `Decimal("0.10")`, `initiative_dice` 3, natural REA 4 /
augmented 6, Sneaking 7, `nuyen_remaining` 580, and both Rating-3 parents' Capacity at exactly 12/12.
WP85's acceptance criteria say to *stop and log* if an engine or `io` change turns out to be needed,
since that would mean the format regressed at some point since WP41. None was.

### Registry shape: copied, not referenced — the inverse of `mundane_chum5.py`

`mundane_chum5.py` deliberately *points at* `legacy/Chummer.Tests/TestFiles/` rather than copying
~9MB of vendored XML into `tests/`. The reasoning there was about duplication and drift against an
upstream source of truth. Neither applies here — a native save is a few KB and there is no upstream
copy for it to drift from — so `native_saves.py` holds the files under `tests/fixtures/saves/`
directly. Worth stating explicitly in both modules' docstrings, since two sibling registries making
opposite calls looks like an inconsistency until you know it's the same reasoning run in both
directions.

### What the test asserts, and what it deliberately doesn't

Three tests, two of them parametrized over the (currently one-entry) registry so a second native save
costs nothing to add:

- **It still loads and builds.** The broadest statement of the regression, and the one that would
  fire first on a format break.
- **`from_json → to_json → from_json` is stable**, and both build to the same Essence. Deliberately
  *not* `to_json(save) == original_text`: that would pin down key order and whitespace, which this
  format has never promised, and would make a harmless field reordering look like a data loss.
- **The six headline values**, each chosen because it is a *different* mechanism's output rather than
  six readings of the same number.

What it doesn't do is hand-derive those six from the rulebook with citations. That is WP88's job, and
conflating the two would have made this file a second rules test rather than a save-format guard. The
distinction matters for what a failure here *means*: if `test_razorboy_headline_values` breaks, the
question is "did the format change?", not "is the rule right?"

`_load` lets `Path.read_text` raise `FileNotFoundError` rather than skipping — a silently-skipped
regression test is indistinguishable from a passing one, which the acceptance criteria call out
directly.

## Result

- `tests/fixtures/native_saves.py` — the registry (`NATIVE_SAVE_FIXTURES`, `RAZORBOY_SAVE`,
  `native_save_path()`).
- `tests/integration/test_native_save_fixtures.py` — 4 tests.
- `tests/fixtures/README.md` — a section for the third fixture family.
- No `src/` change, as intended.

`pytest` 1219 passed, `ruff`/`mypy` clean.
