# WP99 — The remaining-resources panel

Phase W's third WP. The sketch's sidebar has a box under the step nav showing what is left to spend.
This WP builds it. It is one always-visible list of the global budgets, and it stays current from
any page without any step route knowing about it.

## What landed

- **`Character.nuyen_spent`** (`engine/character.py`) is the one new piece of engine logic. It sums
  the six committed spenders of Step Six's shared pool: gear, primary lifestyle, cyberware, bioware,
  foci, and vehicles/drones. It is `karma_spent`'s nuyen counterpart.
- **`chummer5.web.shell.resource_panel_context(session, chargen_ctx)`** builds one row per budget,
  each with its remaining figure, its total, and an `over` flag for a negative pool.
- **`_resource_panel.html`** is included under the nav in `base.html`'s sidebar. It is a
  `<section>` holding a `<dl>`, with a placeholder before any character exists.
- **`GET /ui/resource-panel`** (`routes/pages.py`) returns the panel alone. The panel re-fetches it
  on `chargen-changed`.
- **`app.css`** has `.resource-panel*` rules and two new tokens, `--panel-muted-fg` and
  `--panel-over-fg`, for both schemes.
- **`tests/unit/test_web_resource_panel.py`** has 8 tests.

## Decisions

### What the panel shows, and where each number comes from

The entry's one hard rule was that the panel must not become a second accounting path, so every
row reads a number that already exists:

| Row | Source |
|---|---|
| Karma | `Character.karma_remaining`, of `STARTING_KARMA` |
| Nuyen | `available_nuyen(resources_letter, PRIORITIES, karma_converted) - Character.nuyen_spent` |
| Attribute points / Special attribute points | `chargen_ctx["primary_*"]` / `["special_*"]` |
| Skill points / Skill group points | `chargen_ctx["skills_*"]` / `["groups_*"]` |
| Knowledge points | `chargen_ctx["knowledge_free_points"] - ["knowledge_points_spent"]` |
| Free spells (Magician only) | `chargen_ctx["spells_remaining"]` / `["spell_budget"]` |
| Power Points (Adept only) | `chargen_ctx["power_points_remaining"]` / `["power_point_budget"]` |

Nuyen was the one pool without an existing total. Every step that shows a nuyen figure receives the
*other five* sections' costs as arguments and sums them itself. Reading any one step's
`nuyen_remaining` out of the merged context was not an option: that key is returned by the
resources, cyberware, and character-sheet contexts, and the merge keeps whichever came last. That
is the same clobbering WP60 fixed for the Karma keys. So the sum moved into the engine, where
`karma_spent` already does the same job for Karma.

The point pools are read off `chargen_ctx` rather than recomputed. `chargen_context` already builds
every step context from committed state on every full render, and those figures are exactly what
each step prints on its own page. The test pins the agreement against the pages' own wording
("Primary attribute points remaining: 17 / 20.").

**Left out:** Essence, which is not a spendable budget in the sketch's sense, and Contacts' free
points. The latter are only exposed under the generic `free_points` key, which is exactly the kind
of collision-prone key this panel avoids. Adding them is a one-key rename in `contacts.py`, which I
left for whoever next opens Contacts.

### The panel sits above the per-step lines, not instead of them

As the entry recommended, and recorded in the decisions log. The per-step lines are scoped
differently. The Skills page's "Karma remaining for skills" is the Karma available to that step's
spend, which already counts its own previous spend as available. The panel's Karma is the global
ledger after everything. Replacing the step lines would lose the first figure.

### Self-refresh, not an out-of-band swap

The entry says "re-sent as an htmx out-of-band swap from every step's `POST`". WP97 replaced that
approach for the nav and logged why: fifteen routes, each rendering something it does not own. The
panel uses the same `chargen-changed` event. The acceptance test for "OOB swap present in a `POST`
response" became a test that the panel carries `hx-get="/ui/resource-panel"
hx-trigger="chargen-changed from:body"` and that step `POST`s emit the event.

Three self-refreshing widgets (nav, tab strip, panel) now mean three `GET`s per change. I timed
them: about 3 ms each against a TestClient, with the page render itself at about 7 ms. That is not
worth an aggregate endpoint in a local, single-user app. If it ever matters, `/ui/nav` could return
the panel and tab strip out of band in one response.

### Over-budget is flagged, not clamped

A priorities change can leave a committed spend over its new budget (WP19). The panel shows the
negative figure and marks the row `--over` in the error colour. It does not clamp to zero, because
"−3 of 22" says exactly what the player has to undo.

## Traps hit

- None of substance. The one design trap was the colliding generic keys, described above.

## Verification

- `pytest` 1379 passed (8 new). `ruff check`/`ruff format --check` clean; `mypy src` clean.
- A Playwright walk against a live `uvicorn`, with no console errors:
  - The panel shows its placeholder before any character exists.
  - After confirming priorities it shows all seven mundane rows.
  - Setting BOD 3 on the Attributes page moves "Attribute points" to 17 of 20 without a reload.
  - Choosing a Low lifestyle on Equipment → Lifestyle moves Nuyen to 48000¥ of 50000¥.
  - The screenshot showed wrapped rows ("Special attribute points") dropping the figure to the
    left edge. Fixed with `margin-left: auto`.
